# CLAUDE.md: Agent Office for Claude Code

A browser office for Claude Code sessions: bots at desks, a chat per bot, approvals, diffs, schedules. Node ES modules, no dependencies, Windows first. User docs are in `README.md`. The UI is the Agent Office design system (DS x1.6.7), documented in `DS-README.md`, `Recipes.md`, `Reference.md`, `Concepts.md`.

## UI rules (the DS is law for anything visual)

Read `DS-README.md`, `Recipes.md` and `Reference.md` before you change the UI, and follow the DS Rules and Definition of done.

- Use DS tokens for every color, size and duration. No literal colors. Use the DS icon set and DS components (`Button`, `Dialog`, `Select`, `TextInput`, `EmptyState`, ...). No emoji.
- Write copy in Simplified Technical English: short sentences, active voice, buttons say the result. No "Oops", "Sorry", exclamation marks, "please".
- Keep the `x` version prefix (page `x0.1`, DS `x1.6.7`) in titles.
- The DS lives in this repo and its owner may change it. DS changes go in `components/`, `kit/`, the tokens and the DS docs, with a Changelog row and the DS Definition of done (`DS-README.md`). Page code still uses only DS APIs: no DOM patching of DS internals.
- Never move bots yourself. The scene changes only from adapter events.
- Before you finish a UI change: `python kit/check.py public/index.html public/office.css public/office.js public/adapter.js public/chat-extras.js public/city.js public/board.js public/terminal.js public/wheel-gate.js public/vocab.js public/scene-host.js public/building.js public/format.js public/toasts.js public/wire.js public/security.js components/bundle.css components/bundle.js kit/page.html`, then look at screenshots in Day, Night and Sublevel at 1360, 1100 and 400 px.
- In-scene controls (the Security room screens) have no keyboard or screen reader path (ADR 0003, the exception line in the DS Definition of done). Do not add one.
- The page's own styles go in `public/office.css`. The DS sets its theme on `.ao-office`, and `chat-extras.js` mirrors it to `<html data-theme>`, so page UI must read tokens only.

## Commands

```
npm start            # server on 127.0.0.1:4317; prints and opens a one-time launch link (OFFICE_OPEN=0: print only). Again while it runs: a new link
npm run start:branch # server on the port of this checkout's branch (4330-4399); OFFICE_OPEN=0, so it only prints the link
npm run probe        # prove HTTP hooks on this Claude Code version (one tiny call)
npm run smoke        # end-to-end test with real Haiku sessions, a few cents; needs the office running
```

Stop the server by the pid that owns port 4317 (`netstat -ano | grep :4317`, then `taskkill //PID <pid> //F`). Never kill by image name: that would kill other Claude Code sessions.

Owner rules for final tests and clean-up:

- Final browser tests in a worktree run on that worktree's own port, from `npm run start:branch`. Never on 4317 (the owner's office) and never on a hand-picked port. The port comes from the branch name (`git.branchPort`: FNV-1a, range 4330-4399), so it is the same every time on every machine. If that port is busy, the office stops and names the port and the branch; it never takes another port. Stop it by the pid that owns its port, as above.
- `OFFICE_PORT=branch` is the same switch for any other start. A detached HEAD uses the worktree folder name. Two branch names can share a port (70 ports): rename the branch, or stop the other office first.
- When a branch is merged, remove its worktree and its branch. Close a finished office session.

## How data moves

- Hooks (HTTP or command) post to `/hook/http` or `/hook`. `PermissionRequest` is held until `/api/answer`, or until it times out (60 s for terminal sessions, 15 min for office sessions).
- `PostToolUse`, `UserPromptSubmit` and `Stop` can return queued office messages to the session.
- The Security room rules (#70, `security.mjs`) come before every hold. The tracker's screen rates the request (`actionOf` against `rootOf(s)`, the session's agent kind, its building once placed, else the office-wide rules): Allow answers at once, Deny refuses at once with "Denied by the Security room: <row>." to the agent, Ask holds as before. Each automatic answer writes a feed line ("allowed by Security: Edit inside the worktree"), except a low call a provider asked about under its default Allow (quiet). A hook gets the answer in its reply; a provider gets it through `answer` on a later tick. Claude Code's `PreToolUse` refuses a Deny before Claude Code's own check (so its allow rules and modes cannot run it; `tracker.refuseCall` ends the call) and asks for a tightened read or edit inside; `PreToolUse` never allows. A Claude Code office session (open, reopen, schedule, terminal window) opens in `default` mode while any of its cells is Ask, and the feed says so when that overrides the asked mode. An ungated kind that is off, or a kind without cost reports set to Deny, is refused before a worktree is made (409). Defaults copy `riskOf`: low is Allow, the rest is Ask, so an edit inside the worktree that Claude Code asks about is now answered by the office.
- `POST /api/security/set` (page group) takes one change from the wall: `{ scope: 'office' | 'building', building, row, col, value, confirmed }`. A looser change without `confirmed: true` is 409; Allow on a Secrets row is 400. Each change writes a feed line. The rules live in `state.json` (`persisted.security`), the month's cost per agent kind in `persisted.costs`. The snapshot carries `security: { rules, enforce, spend }`.
- An office session runs in its provider (`providers/`). The server calls `open`, `message`, `answer`, `interrupt` and `close`; the provider reports through `providerEvents` into the tracker. For Claude Code the session is `claude -p --input-format stream-json --output-format stream-json --verbose --include-partial-messages`. Messages and control requests go to stdin. Stdout messages go to `onStream()`; a control response goes back to its request in the provider.
- A provider reports in the tracker's vocabulary: hook-shaped events (`events.hook`, trimmed by `slimPayload` like the hook route), stream messages (`events.stream`), and requests it holds itself (`events.permission`). Two timing rules: a method returns before the events that follow from it (the office calls `startTurn` after `message` and `tracker.interrupt` after `interrupt`), and a provider reports nothing after `close` or `events.end`.
- A held request ends with one decision: `{ allow, always }`, `{ text }` for a question, or `{}` for none. The hold's `reply` takes it to the agent. On a hook, the session's provider gives the answer body (`claude.answer`: `hookSpecificOutput`). `POST /api/open` takes `provider` (default `claude-code`). `GET /api/providers` gives each kind's readiness, needs and models. A hold that times out says "question timed out, <provider label> moved on".
- A provider delivers `events.hook()`'s return value (queued office messages: `additionalContext`, or `decision: block` on Stop) to its agent.
- Past sessions record `provider` and `model`. Reopen follows `providers.reopenPlan(rec)`: a provider with `canResume` continues the conversation and the record leaves the past list; any other provider opens a fresh session in the same folder with the same model, the feed says "A new session started. This agent kind cannot resume a past session.", and the record stays. A record with no `provider` is Claude Code's.
- Every state change calls `broadcast()`. Changes within 100 ms go out as one message. A page gets the lean snapshot whole when it connects, then one patch per broadcast (`public/wire.js`); `store.receive` applies it, and a patch that does not fit makes the page connect again. When the page starts to read a new session field, add it to `SESSION_FIELDS`, or the page never gets it. Full data of one session (sid, budget, every reply, its feed lines) is `GET /api/session?uid=`; tests and scripts read that, not `/events`.
- Sessions are keyed by `uid`. `sid` is the agent's session id (Claude's for Claude Code). `officeId` links hooks to a session the office opened (env `OFFICE_ID`).

- Access (owner decision on #27 H1, rules in `auth.mjs`). Two tokens, each for one route group, neither opens the other:
  - Agent token: `/hook`, `/hook/*`, `/mcp/*`, in `x-office-token`. Kept in `.office-token` (`{ token, port }`, read by `hook.mjs` and `mcp.mjs`) and in `office-hooks-http.json`. Reused across restarts.
  - Page token: `/events`, `/api/*`, in the page cookie `ao_<port>` (HttpOnly, SameSite=Strict, Path=/, no expiry date) or in `x-office-token` from the user's own tools. New at each start. Never in the office folder: in server memory, and in `pageFile()` = `%LOCALAPPDATA%\AgentOffice\office-page-<port>.json` (`{ token, port }`) for `probe.mjs`, `test/smoke.mjs` and a second `npm start`. `risk.mjs` rates a read of that file as a secret.
  - Launch code: at `listen` the server mints one, prints `http://127.0.0.1:<port>/#n=<code>` and opens it (`cmd /c start ""`, off with `OFFICE_OPEN=0`). `adapter.js` removes the code from the address bar and sends it to `POST /launch` (public, JSON, same origin). A code works once, for 5 minutes; the answer sets the cookie. `POST /api/launch-link` (page token) mints another; a second `npm start` that hits EADDRINUSE uses it and opens the new link.
  - Public: `GET /`, `/favicon.ico`, the static files (`STATIC_FILES`, an exact-match map from URL path to file; the request path is never part of a file path). `GET /` holds no token.

- Room awareness: `office_room` describes the room of the calling session. `office_room_update` changes only that room's notes board (`persisted.notes[key]`, kept as `{ text, at, v, by? }`: `v` is the version counter, `by` is set when an agent wrote it) and one blackboard pin (`persisted.pins`). Each line an agent appends starts with the session name. A rewrite returns the old text in the reply. All of these rules live in `notes.mjs`; `server.mjs` only calls it and saves the maps.
- `POST /api/notes/save` takes `{ key, text, base, sent }`, where `base` is the version (`v`) the editor started from. `sent: true` means the editor typed on while a merged answer came back, so `notes.mjs` merges against the text the editor sent with version `base` (kept as `sent` on that remembered version), not against that version's board text. When the board moved on, `notes.mjs` merges three ways against the text of that version (kept in memory, last 12 versions per board; an older base falls back to the server text plus the user's new lines) and the answer is `{ ok, version, text, merged }`. The editor shows `text` when `merged` is true. There is no 409. A cleared board keeps its counter (`text: ''`, `at: 0`), so a version never comes back with other text. Over the 4000 character cap (also for a merge result) the answer is 413 and nothing changes.
- `office_room` lists the decor of a lab room under "What is in the room" from one list in `roomContents()` (server.mjs), next to the fixed lab-room parts and the street. The list is the same for every room, so the page does not report it. Keep it in step with `board.js`.

- Place rules live only in `place.mjs`. Room id = readable tail of the folder plus a hash of the whole normalized path, so look-alike folder names stay two rooms. Paths are normalized and lower-cased, so path case never makes a second building. A session outside git has building key `''` (name "Other folders") and notes key prefix `other`. `adoptNotes()` in `server.mjs` moves a note or pin saved under an old key (room id without hash) to the new key when its room is first seen. `git.locate` gives null both outside git and when git fails for a moment, so `placeSession` in `tracker.mjs` keeps the last known place when a lookup in the same folder gives null. A new folder is believed.
- Session rules (status, tool calls, subagent links, the 60-call cap, errors, budget stops, interrupts) live only in `tracker.mjs`. Rules read the clock, ids and timers only through `now()`, `makeId()` and `setTimer()`. Their real defaults are at the top of `createTracker` and nowhere else. Never call `git` or `broadcast()` from the tracker: use `deps.locate` and `deps.onChange`. Test a rule in `test/tracker.test.mjs` with the fixtures in `test/fixtures/` (small stand-ins, shapes checked against a real recording; subagent `agent_id` payloads are not recorded yet; no paid call). The server keeps the parts that need a socket: the permission and question holds (`holds`) and `sendMessage`. The parts that need a process (spawn, stdin, control requests, `taskkill`) are the provider's. A provider never passes a bare program name to spawn or execFile: it uses `resolveExe`, and `test/spawn-safety.test.mjs` scans `providers/` too.
- Add a place field in `place.mjs` and read it from `s.place` in the page. Do not rebuild keys in `building.js`, `office.js` or `board.js`.

- Status words, task lines, tool names and kinds, to-do status and room figures live only in `public/vocab.js`. Do not write a second copy in `building.js`, `adapter.js`, `office.js`, `terminal.js`, `board.js` or `server.mjs`. The server computes room figures once per snapshot (`snapshot.figures`, keyed by notes key); the page reads them with `mount.figures(roomId)`.
- Waiting = a pending permission prompt or an open question (`isWaiting`). The `status` field alone does not count, and a subagent's tool call does not hide a request.
- A tool result settles one permission request: the oldest one with the same `callKey` (agent, tool and trimmed input). Never match on the short label from `describeTool`: it keeps only a basename or the start of a command.
- A permission request is rated against the session's root (`rootOf` in `tracker.mjs`): `worktree.root`, else `startDir` (the office's launch folder, or the first `cwd` a hook reported). Never against the live `cwd`: it follows the agent, so a `cd` would widen what is low risk.
- Agent rooms (#69, spec #67). An agent is a top-level session (`uid`); a subagent is a guest in its parent's room (a provider reports it with `agent_id`; the rule is in the `events.hook` note of `providers/index.mjs`). `POST /api/open` makes a new worktree for the agent unless `isolation: 'same'` ("Use this folder" in the open dialog); a terminal window and a folder outside git work in the folder (outside git the feed says so). The default changed with #69: a caller that omits `isolation` (API, scripts) gets a worktree. Schedules still choose their own `isolation`; a schedule with `isolation: 'worktree'` makes a new worktree and branch on every run, and the office never removes them (a follow-up: reuse one worktree per schedule). The room of an agent worktree sits on the floor of its base branch, so three agents are three rooms on one floor. Terminal sessions in one folder, or sessions with "Use this folder", share the room: the door sign (the page's sign on the room; the DS room name sign keeps the branch name, and is not ours to change) says "N agents" (`OfficeVocab.agentsSign` over `figures.sessions`, helpers do not count). The office never moves a terminal session and never removes a worktree by itself.
- Reopen keeps the past record until the reopened session has a `sid` (`reopening` in `server.mjs`). The tracker saves a session the moment its sid first arrives (init line or first hook), so the record swap happens then, not at the first turn end. While the reopened session is live and not ended, its past record is hidden from Past sessions and a second reopen answers 409. A reopen that ends before init keeps the record and shows Error through `tracker.fail`; a close the user asked for gives no error (#54).
- A failed turn shows as Error on every surface until Dismiss (`POST /api/dismiss`, `tracker.dismissError`) or the next turn starts (`tracker.startTurn`, or the `UserPromptSubmit` hook).

## Gotchas learned the hard way

- `OFFICE_OLLAMA_URL` and `OFFICE_LMSTUDIO_URL` move the local providers to another server on loopback. `createLocal` refuses any host that is not loopback, and then the office stops at start. The tests use them to point at the fake server (`test/fixtures/fake-openai.mjs`).
- The local provider sends only `model`, `messages`, `tools`, `stream` and `stream_options`, by POST to `/chat/completions`. LM Studio can run its own MCP servers (for example run-command) when a request names them. Never add a field or call another endpoint: a tool call could then skip `riskOf` and the approval check. `test/local-provider.test.mjs` fails on any other key or path.
- A test that starts `server.mjs` copies the code to a temp folder first (`test/mcp-routes.test.mjs`, `test/auth.test.mjs`, `test/static.test.mjs`, which also copies `components/` and `tokens.css`): the server writes `state.json`, the hook files and `.office-token` into its own folder, and a second copy in the repo would overwrite the token of the running office. It also sets its own `OFFICE_PORT`, `LOCALAPPDATA` (the page file goes there; the test reads the page token from `auth.pageFile(env, port)`) and `OFFICE_OPEN=0` (no browser).
- The dock (`.strip`) is measured by `office.js`, which sets `--strip-clear` on `<html>` (its height plus a gap). The DS chat, roster, Since you left card and the page panels use it as their bottom edge. Do not hard-code a bottom offset for them. `kit/check.py` counts custom properties that the page defines in its own CSS as known tokens, so `--strip-clear` has a default in `office.css`.
- The scene height is `office.js` state (`win.h`): a resize renders the page again, and the DS sets the new inline height. Do not override the `.ao-office` height in CSS (#55).
- One card in the middle: the welcome card waits while the DS Since you left card shows (`onSinceYouLeft` sets `syl`), and the dock's Open session is the primary button then. At 820 px and below the room card waits too, because both sit on the dock (#66).
- `backdrop-filter` on `.strip` makes it the containing block of its fixed children, so the More popover is `position: absolute`, not fixed.
- One panel at a time: `office.js` adds `has-panel` to `#office` while the terminal, board or stats panel is open, and `office.css` hides `.ao-hud-right` (the DS chat and roster) then. Every such panel must show `RequestBar`, or an approval could hide behind the hidden chat.
- "Always allow" and the risk of a request come from `OfficeVocab.alwaysOffer / requests`. A question has no risk and no rule. A high-risk request never offers Always allow.
- Recent folders are kept by `place.mjs` (`addRecent`, `cleanRecent`): one form, no duplicates in any case or slash style. Do not compare folder strings by hand.
- Spend limit rules live only in `providers/index.mjs` (`spendLimitFor`, `isPaid`, `DEFAULT_SPEND_LIMIT` = 2). A provider is paid unless it says `paid: false` (the local ones). Missing value = the default (`persisted.spendLimit`, changed in the Attach sessions dialog, `POST /api/settings/spend`); 0 = the user cleared it; a local provider never has one. `server.mjs` (open, schedules) and `manager.mjs` (goals) call it; the page only fills the field from `info.spendLimit`.
- Bot body color comes from `OfficeBuilding.colorOf(uid)` (the DS color of its shape) and is sent to the scene in the bot definition. Lists read the same value, so a bot looks the same everywhere.
- `cmd /c start "Office" ...` needs the quoted title. Unquoted, `start` runs a program named Office.
- Write `.office-token` and the page file only after `listen` succeeds. A second copy that fails with EADDRINUSE must not change them. The agent token is reused across restarts on purpose; the page token is not (a restart needs a new launch link, and open tabs ask `/api/auth` every 5 s until a link opened in any tab gives the browser the new cookie).
- Never put the page token where an agent reads files: not in `GET /`, not in a file in this folder, not in a URL. Never accept a token from the URL (`?t=` opens nothing, also on `/events`: the cookie authenticates EventSource). The page holds no token in JavaScript; its `fetch` and `EventSource` send the cookie by themselves.
- Compare tokens and launch codes only with `auth.tokenEqual` (hashed, `crypto.timingSafeEqual`, any length). `test/auth.test.mjs` fails on `=== AGENT_TOKEN` style compares in `server.mjs`.
- Cookies do not keep ports apart, and SameSite counts every port of 127.0.0.1 as the same site. So the cookie name has the port (`ao_<port>`), and `checkRequest` refuses a foreign `Origin` and a `Sec-Fetch-Site` of same-site or cross-site on token routes. A POST must say `application/json` (Claude Code HTTP hooks, `hook.mjs`, `mcp.mjs` all do), so a form or a plain-text post from a page cannot reach a route.
- `X-Frame-Options: DENY` and the CSP (`auth.CSP`: `frame-ancestors 'none'; script-src 'self'; style-src 'self'; font-src 'self'; object-src 'none'; base-uri 'self'`) go on every response with `res.setHeader` at the top of the handler; `setHeader` merges into later `writeHead` calls, so held hook answers get them too. So the page has no inline `<script>`, no `on...=` attribute, no `style="..."` in markup or `setAttribute('style', ...)`, no `eval` or `new Function`, and no file from another site. A new page script or style sheet is a file in `public/` with an entry in `STATIC_FILES`. React `style` props are fine (they go through the DOM). Never add `'unsafe-inline'`, `'unsafe-eval'` or a CDN to the CSP; `test/auth.test.mjs` fails on them. Images stay open on purpose (see the chat image rule below).
- `public/vendor/**` is `-text` in `.gitattributes`. With `core.autocrlf` (Windows default) git would write CRLF at checkout and the pinned SHA-256 in `test/static.test.mjs` would fail. Change a vendored file only with the steps in `public/vendor/README.md`, and update the pins in the same commit. `STATIC_FILES` reads the font names once from `public/vendor/fonts` and serves only names that match `^[a-z0-9-]+\.woff2$`.
- Remote images in chat load only after a click. The rule is in the DS RichText (`components/bundle.js`: `remoteHost`, `imageShown`, `LoadCard`, `shownImg`): an http(s) image shows the card "Load image from <host>" until the user clicks; the click counts for that URL until the page reloads; `data:` and `blob:` images show at once; the image viewer asks the same way; images carry `referrerPolicy: no-referrer`. Agent replies reach it because `building.js` sends them as Markdown `message` events. Never render agent or tool text with your own `<img src>`, and do not send it with a `thumb` or image attachment of a remote URL. `test/rich.test.mjs` runs the bundle in a Node VM with the vendored React and a shallow renderer (stand-in hooks); use it for other DS logic too.
- Files with a token (`.office-token`, `office-hooks-http.json`, the page file), settings files whose commands sessions run (`office-hooks.json`, `office-mcp.json`), and the saved state and past sessions (`state.json`: schedule prompts and notes; `history.json`: replies; #27 L10) are written with `writeSecret` (server.mjs, `auth.writeOwnerOnly`, icacls through `resolveExe('icacls')`). `state.json` and `history.json` go through it once, in the `listen` callback (so a second copy never rewrites them), with what the office loaded; `savePersisted` and `saveHistory` then write plainly and keep the ACL. A new file that holds user or agent text joins that list the same way. Only the user, SYSTEM and Administrators keep an entry (`KEEP_SIDS`, by SID so it works in every language): SYSTEM and Administrators can take ownership of any file anyway, and to deny them breaks backup and antivirus. Steps: make the file if missing, `icacls <file> /inheritance:r /grant:r DOMAIN\user:F *S-1-5-18:F *S-1-5-32-544:F`, read the ACL back by SID (`readAcl`: Windows PowerShell runs `auth.ACL_SCRIPT`, .NET only, about 0.2 s), and check it with `aclProblems`: inheritance off, owner one of the three, and one explicit allow with full control for each of the three. Never accept a count of entries alone: a list of three can be three inherited entries. `/inheritance:r` removes inherited entries only, and a new file in a folder with nothing to inherit gets explicit entries from the token's default DACL (an elevated admin, as on GitHub's runner: SYSTEM, Administrators, sometimes OWNER RIGHTS; a normal user: the user, SYSTEM and `LogonSessionId_*`). So when the check fails, the writer runs `/inheritance:d` (inherited entries become explicit), `/remove` for every other SID and every deny, the limit again with the user by SID, and checks again; if it still fails, the warning names the file and what is wrong. No step widens access, so the file is never emptied and there is no `/reset`. SDDL is no use for the check: it writes a RID-500 account (GitHub's `runneradmin`) as `LA`. A later `fs.writeFileSync` keeps the ACL. A failed icacls or PowerShell prints a warning and the office runs on. Test real ACLs by SID in folders the test sets up itself with .NET (`aclOf`, `folderAcl`, `wideFolder` in `test/auth.test.mjs`), never by account name, never in the repo folder, and read each folder back before you trust it. The office folder itself keeps its drive's ACL (on E: Authenticated Users can change files); per-file ACLs do not fix that.
- A headless session emits `init` (session id, commands, skills) only after its first message. The server keeps the last command list for new sessions.
- Claude Code's default permission mode may be Auto, so no prompts appear. Tests that need a prompt must pass `permissionMode: 'default'`.
- The hook's parent shell dies right after the hook returns, so the process walk must happen while the hook waits. A persistent PowerShell helper (`walkToClaude`) does it.
- Every program the office starts names its `cwd`: the session folder for work in it, `git.helperCwd()` (%SystemRoot%) for a helper. On Windows a process keeps its current folder busy, so a helper that inherited the office folder (the walker, icacls, the ACL reader) made `rmSync` of a test's temp office fail with EBUSY after the server was killed (#78). `test/spawn-safety.test.mjs` checks the sources.
- HTTP hook failures are non-blocking. Command hooks must stay silent on stdout unless they return real hook JSON.
- "Always allow" uses `permission_suggestions` from the hook payload and returns them as `updatedPermissions`. Pass only `addRules` with `behavior: allow`. Edits get a mode suggestion, not a rule.
- `result` with `error_during_execution` after an interrupt is not an error. Check `s.interrupted`.
- Hooks fired inside a subagent carry `agent_id`. Use it to put the call on the helper bot, and keep it off the parent's task line.
- `room.add` needs `floorId`. The building's floor has `id: 1` for that reason.
- The DS weekly-limit meter shows demo numbers when no `usage` events arrive, and its engine adds usage while bots work. The server reads `rate_limits` from the status line file; the adapter re-sends the figure every 15 s; `office.css` hides the meter without it and always hides the per-bot rows.
- One scene shows one building, and each scene gets its own building adapter (`officeAdapter.mount(repo)`). `office.js` keeps it in `cur2.mount`; its React key is `'m' + mount.id`. The adapter holds the mirror, the layout and the bot names, so there is no global reset and no generation counter. The SSE stream and the latest snapshot belong to the store, not to the scene.
- The DS has no event that removes a floor or a room. `mount.stale()` is true when the scene shows a room that is gone, or was empty and now has rooms. `office.js` then fades the scene out and mounts a new adapter. Dialogs that need a room (`RoomDialog`, `StatsPanel`) take `mount` as a prop. `officeAdapter.session / lookup` look in the adapter that is attached now.
- Ctrl+K page commands are built from App state each render and handed to the palette in an effect (`pageActions`). Room tools (`board.open`) and session commands (terminal, changes, Stop turn, Go to) are built by `liveActions()` at that moment, so the rooms of the floor on screen are current. The DS calls `CommandPalette.actions` on every scene render, so `liveActions()` runs on each scene event; keep it cheap. Do not mutate a module array during render.
- Esc closes the top layer only. A dialog (`.ao-dialog`) or the palette (`.ao-cmdk`) takes it first; a DS Dialog is gone from the DOM before window bubble listeners run. So decide in the bubble phase with `OfficeBoard.escTaken(e)`, which records the layer state in window capture. Do not move the handler to capture: `chat-extras.js` stops Esc for the `/` list there.
- Needs you is `officeAdapter.requests(snap)`, not a sum of the DS inboxes (they list one building). The page runs the one `Notifier` (the scene gets `notifier: false`): its `count` is the Needs you total, so the tab title counts every building, in the city too, and its notifications are `officeAdapter.alerts(snap)` (requests and errors of every building). The DS `ao-alerts` setting turns the alerts on. Do not mount a second `Notifier` with a title: two of them write the title over each other.
- The Decisions inbox is page state: `OfficeScene` gets `inbox` and `onInbox`. A page panel that opens closes it (`setInbox(false)`); a new scene starts with it closed in its first render (the state carries its scene key). Do not read or click DS inbox class names.
- A new scene starts empty, and `building.js` sends the whole state again with `seeded: true` (DS Reference, Scene mount). Seeded events record no history, play no sound and send no `onNotify`, so Since you left shows on every scene and counts only news (a seeded event with `at` after the last visit). Choice: a seeded request or error makes no toast. It was news once, when it arrived live. An open request stays in Needs you, the DS inbox and the tab title; the Since you left card counts it when it came in after the last visit. The first pass sends open requests, questions, replies (no speech bubble) and the error at once, not one snapshot later. A restore inside a live pass (a bot seated again, or a bot that moves in from another building with its error and its replies, which also covers a round trip and a reopened session that carries its old replies) is seeded without `at`: a seeded event with `at` after the last visit is news to the DS, which would record it a second time. A request is never restored that way on first sight: a missed request is worse than a second toast.
- The notes editor takes focus when it shows and again when the camera lands (it checks `host.flying()` each frame). Its font is never under 16 px.
- Room screens take two steps (`scene-host.js`). The first click looks: the camera flies so the plane fills 88% of the free part of the view, the box that `freeRect` finds between the page's covers (`sceneCovers()` in `office.js`: HUD columns, the dock, a side panel, the look bar). A second click on the same screen opens it (the target's `open`); a click on another screen looks at that one; Esc, Back or a click on empty scene flies back to the camera the first look saved. Only the host moves the camera; adapters give a `look(item)` spec (`key`, `mesh`, `verb`, `kind`, `clear`) and a `find(key)` for floor rebuilds. After the landing the camera stands `clear` units in front of the screen: the view is orthographic, so only the clipping changes, and the bot, its bubble and the desk in front are cut away. The camera steps back out on its line of sight before any flight, so the cut never sweeps through the room. While a screen is in focus the host holds back a new `st.goal` where it is set (an accessor on the stage; the engine applies a goal before the page's frame, so clearing it there let one frame through, and selecting a bot makes the DS HUD reframe the floor), lets the held goal run when the floor or the view changes, widens `ctl.maxZoom` for the wheel, and the wheel gate does not leave the floor. A theme change rebuilds every floor and the DS frames the floor at once (zoom 1); the host puts the camera back on the screen in the same frame. Picks wait for the DS intro to end. The page listens with `host.onFocus`: a look shows the look bar and closes the panels; `refit()` runs when a side panel opens, the dock changes height or the window resizes.
- The DS has no `room.remove` or `floor.remove`. The page rebuilds the scene (a new React key) when a shown room is gone.
- Two worktrees on one branch need `git worktree add --force`.
- Room boards are matched to rooms by order: the shown floor's lab rooms, left to right (`OfficeSceneHost` `host.rooms()`), against the chalkboards (4 x 2.5 planes). The engine rebuilds a floor when a bot joins or the theme changes. The host sees that (new bot list, floor, floor groups, theme tokens, or a lost anchor) and fires `onRebuild` before the frame draws; board.js and terminal.js rescan then, and still on a 1.5 s timer.
- Only `public/scene-host.js` reads the DS stage's floors, views and room geometry. A new scene decoration registers a frame (`host.frame`), a rebuild listener, and, if it can be clicked, a pick target (`host.register`). Do not add a pick Raycaster (one that turns the pointer into an action), pointer listeners or `canvas.style.cursor` writes in another file: two raycasts gave two actions for one click. Geometry raycasts that do not react to the pointer, like terminal.js placing the desk light, are fine. The building view is `host.inBuilding()` (no floor group is visible), not the Building button's `aria-pressed`.
- The scene fades out (`duration-base`) before any rebuild: another building, the city, a removed floor or room. Labels in the city sit on layer 1 so the bloom pass skips them.
- Extensions: `mcp_status`, `mcp_toggle`, `mcp_reconnect`, `reload_plugins` are control requests on the session's stdin; they work before the first prompt. Persistent changes use `claude mcp` and `claude plugin` with scope local or project only.
- A trackpad flick sends wheel events for about a second, some after the finger lifts. Scroll-out goes through `OfficeWheelGate`: events less than 140 ms apart are one gesture, and a gesture that changed a level changes no more. Do not count scroll-out wheel events by hand (`city.js` counts zoom-in pushes to enter, which is a different gesture). While the gate holds, `office.js` stops the wheel event so the DS camera feel does not clear the framing.
- A status word on a theme surface (bg, panel, chip) is `--status-*-text` with a dot in `--status-*` (`::before`); on a bubble face it is `--status-*-on-bubble`. A raw `--status-*` is a fill or a dot: it is not 4.5:1 as text in Day. The terminal panel is a `scene-dark` face, where neither text token reads, so its tones mix the status color into `bubble`. `test/contrast.test.mjs` computes the pairs from `tokens.json` and fails on a rule that colors text with a raw `--status-*` outside the pinned mixes. A word that marks something other than a status (a hot file, a building that needs you) stays ink. The DS checker rejects custom properties that are not DS tokens, so write the value in the rule.
- The notes editor and the City label sit on light faces in every theme (bubble, chip). Their ink is the mix `board.js` uses, not `--ink` (light at night). The City label card is the `bg` color (the DS `K.tok` has no `chip` or `line`).
- The City's minimum zoom is Show all (`SHOW_ZOOM` times `s.D` over the fit distance), set every frame in `city.js`. Do not set `ctl.minZoom` to a constant.
- Reduced motion in the 3D scripts: `stage.rm` is read when the stage is made. The DS engine cuts every camera move under reduced motion (`stage.goal` ends on its first step), so `city.js` passes no reduced-motion flag to `stage.frame`. The page's own motion still reads `stage.rm`: city zoom steps and tweens are instant, a building lifts at once, a flight to a room screen and back lands in one frame (`scene-host.js`), the door stays shut and shows a still ring (`d.ring` in `board.js`), terminal cursors are solid (`terminal.js`). The DS engine's own camera moves are the DS's.
- Start every program with `resolveExe(name)` from `git.mjs`, never a bare name. On Windows a bare name is looked up in the child's folder first, so a planted `git.exe` in a repo would run. The entry points also set `NoDefaultCurrentDirectoryInExePath`. `test/spawn-safety.test.mjs` scans the sources for bare names.
- The Bash tool mangles backslashes and quotes in long heredocs. Write patch scripts with the Write tool.

## Safety rules

- The Security room rules decide before any hold, and a looser rule never applies without its painted Confirm (the route refuses it). The two Secrets rows never take Allow. A cell the office cannot enforce for an agent kind must say "Not enforced" with the reason: never show a rule as active when it is not (ADR 0001).
- Bind to 127.0.0.1, check the Host header and the Origin, and require the token of the route's group on every route except the page, its static files and `POST /launch` (which takes a one-time launch code). The agent token never opens `/api/*` or `/events`; the page token never opens `/hook*` or `/mcp/*`. A new route goes into one group in `auth.routeOf`.
- Never edit `~/.claude/settings.json` or `.credentials.json`. The office only writes files in this folder, its page file in `%LOCALAPPDATA%\AgentOffice`, and the per-project rule a user approves. Opening an agent also writes `branch.<agent branch>.officebase` into the repository's `.git/config` and makes the folder `<repo>.worktrees` and the worktrees in it (next to the repository, outside this folder). The key only places the room on a floor and is display-only: an agent can edit it and so choose the floor of its own room, and nothing else reads it. The office never removes these worktrees or branches by itself.
- Extensions change only the local or project scope of a session's folder. User scope stays out of reach, also through `claude mcp` or `claude plugin` (owner decision, 2026-11-03).
- A gated provider holds every tool call that is not low risk until the user answers. Only a provider with `gated: false` skips the hold (owner decision, 2026-11-04, `docs/adr/0001-ungated-agents.md`). An ungated agent shows "Unsupervised" or "Partly supervised", is off until the user turns it on in the Security room, and runs only in a fresh worktree. A setting the office cannot enforce for an agent shows "Not enforced for this agent". The Secrets cells never offer Allow, and ACP agents never get Always allow.
- Pull requests, pushes and worktree removal happen only after an explicit click and a confirm dialog.
- Do not add dependencies without asking. The server runs on Node built-ins. The page loads nothing from another site: React and the fonts are vendored in `public/vendor` (owner decision on #27 M2), and the CSP allows scripts, style sheets and fonts from the office only.
- A remote image in agent text loads only after the user clicks it (DS RichText). `data:` and `blob:` are the only images that show at once.

## Not built

Remote or phone access (needs real login and TLS; suggest Tailscale), terminal sessions taking chat input, non-Windows session launch.
