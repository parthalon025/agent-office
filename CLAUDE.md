# CLAUDE.md: Agent Office for Claude Code

A browser office for Claude Code sessions: bots at desks, a chat per bot, approvals, diffs, schedules. Node ES modules, no dependencies, Windows first. User docs are in `README.md` (short: what it is, how to start it, the five core jobs) and the sub-documents in `docs/` (`using-the-office.md`, `agents.md`, `security.md`, `remote-access.md`, `paperclip.md`, `manager.md`, `customization.md`, `configuration.md`, `troubleshooting.md`, `development.md`). Put detail in the matching sub-document and keep the README short. `test/static.test.mjs` checks every image (alt text and a caption sentence under it) and every relative link in them. The UI is the Agent Office design system (DS x1.7.18), documented in `docs/design-system/DS-README.md`, `Recipes.md`, `Reference.md`, `Concepts.md`.

## UI rules (the DS is law for anything visual)

Read `docs/design-system/DS-README.md`, `Recipes.md` and `Reference.md` (all in `docs/design-system/`) before you change the UI, and follow the DS Rules and Definition of done.

- Use DS tokens for every color, size and duration. No literal colors. A theme (skin) is its tokens plus its `AgentOffice.MODES` and engine `LOOKS` entries: page code reads flags (`K.dark`, `K.caps`, `K.term`) and tokens, never compares a look or theme id with a string, and styles a theme only with a family selector (`[data-theme|="<family>"]`). `test/skin.test.mjs` runs the same checks for every theme of `tokens.json`; to add a theme, follow Recipes, "Add a theme". Use the DS icon set and DS components (`Button`, `Dialog`, `Select`, `TextInput`, `EmptyState`, ...). No emoji.
- Write copy in Simplified Technical English: short sentences, active voice, buttons say the result. No "Oops", "Sorry", exclamation marks, "please".
- Keep the `x` version prefix (page `x0.2`, DS `x1.7.18`) in titles.
- The DS lives in this repo and its owner may change it. DS changes go in `components/`, `kit/`, the tokens and the DS docs, with a Changelog row and the DS Definition of done (`docs/design-system/DS-README.md`). Page code still uses only DS APIs: no DOM patching of DS internals.
- Never move bots yourself. The scene changes only from adapter events.
- Before you finish a UI change: `python kit/check.py public/index.html public/office.css public/page-core.js public/skills.js public/dialogs.js public/schedules.js public/extensions.js public/hq.js public/characters.js public/reception.js public/panels.js public/changes.js public/screens.js public/merge.js public/needs.js public/office.js public/adapter.js public/chat-extras.js public/city.js public/board.js public/terminal.js public/persona.js public/lobby.js public/desk.js public/wheel-gate.js public/vocab.js public/ask.js public/client.js public/screen-kit.js public/scene-host.js public/building.js public/format.js public/toasts.js public/wire.js public/security.js public/vocab-security.js public/vocab-layers.js public/vocab-persona.js components/bundle.css components/bundle.js kit/page.html`, then look at screenshots in Day, Night, Sublevel, Fluent and Fluent Dark at 1360, 1100 and 400 px.
- In-scene controls (the Security room screens) have no keyboard or screen reader path (ADR 0003, the exception line in the DS Definition of done). Do not add one.
- The page's own styles go in `public/office.css`. The DS sets its theme on `.ao-office`, and `chat-extras.js` mirrors it to `<html data-theme>`, so page UI must read tokens only.

## Commands

```
npm start            # server on 127.0.0.1:4317; prints and opens a one-time launch link (OFFICE_OPEN=0: print only). Again while it runs: a new link
npm run start:branch # server on the port of this checkout's branch (4330-4399); OFFICE_OPEN=0, so it only prints the link
npm run probe        # prove HTTP hooks on this Claude Code version (one tiny call); npm run probe -- <port> for an office on another port
npm run smoke        # end-to-end test with real Haiku sessions, a few cents; needs the office running; npm run smoke -- <port> for an office on another port
npm run gate:jobs    # core-jobs gate (#147): five jobs at 1360 and 400 px, fails over the step limits in test/core-jobs.mjs; own office on a free port, own headless Chrome or Edge, no paid call, about 2 minutes; not in CI. Run it before every UI merge
```

Stop the server by the pid that owns port 4317 (`netstat -ano | grep :4317`, then `taskkill //PID <pid> //F`). Never kill by image name: that would kill other Claude Code sessions.

Owner rules for final tests and clean-up:

- Final browser tests in a worktree run on that worktree's own port, from `npm run start:branch`. Never on 4317 (the owner's office) and never on a hand-picked port. The first port comes from the branch name (`branch-port.mjs` `branchPort`: FNV-1a, range 4330-4399), so it is the same every time on every machine. Two branches can share it, so a name has a fixed sequence (`branch-port.mjs` `branchPorts`: its first port, then the next ones, 12 in all, wrapping in the range). The office takes the first free port of the sequence and prints which one (and which were busy). It never leaves the sequence. If an office of the same checkout holds any port of the sequence, early or late (its `/api/info` names a hooks file directly in this folder, read with that port's page file; an office of a worktree below this folder has its hooks file in a subfolder and is another checkout), it stops and says so, so a checkout never runs two. If no port is free it stops and names them. Its files carry the port it took (`files.mjs`), so a probed port writes only its own files. A test that starts an office picks a branch name whose whole sequence is free to hold, so another running office cannot fail it (#96). Stop it by the pid that owns its port, as above.
- `OFFICE_PORT=branch` is the same switch for any other start. A detached HEAD uses the worktree folder name. Two branch names can share a first port (70 ports), and the sequence takes care of it. A branch that takes another port of its sequence than last time starts with the files of that port (empty notes, schedules and past sessions, a new agent token), because the files carry the port (`files.mjs`); an outside session attached with the old `office-hooks-<port>.json` keeps posting to the old port.
- When a branch is merged, remove its worktree and its branch. Close a finished office session.

## Layout

```
src/             every server-side module: server.mjs (the HTTP adapter), office.mjs (the office), office-core.mjs, hook.mjs, mcp.mjs, probe.mjs, the libraries, providers/, integrations/
public/          the page (scripts, styles, index.html, vendor/)
components/ kit/ tokens.css tokens.json   the design system (DS)
assets/          pictures the DS uses
test/            offline tests, fixtures, the smoke and core-jobs scripts
docs/            user and developer documents; docs/design-system/ the DS documents; docs/adr/ decision records; docs/releases.md
launch.ps1       starts a session in a terminal window (the server names it by path)
```

The repository root is the office folder (`files.mjs` `OFFICE_ROOT`, the one constant that knows the layout). The office keeps its runtime files there, never in `src/`: `.office-token*`, `office-hooks*.json`, `office-mcp*.json`, `state*.json`, `history*.json`, and the Paperclip release it installs, `.paperclip-runtime/` (git-ignored; `paperclip-runtime.mjs`). Every module that needs the folder imports `OFFICE_ROOT`; none walks up from its own file. Settings files call `src/hook.mjs` and `src/mcp.mjs`. In the Map and in the rules below, a bare `x.mjs` is `src/x.mjs`. `GLOSSARY.md` stays at the root, where the domain skills look for it.

## How data moves

- Function floors (#92): the server makes a building's record once from `detect(namesOf(dir))` (names only, root and one level down), the first time it knows the building (`layoutRecord`). Only `POST /api/layout { building, action, archetype?, floor?, name?, by? }` changes it (400 with the reason). Each session's seat is `seatOfSession` (in `fullSession`, `session.seat`); the snapshot carries `layouts`, `rooms` (notes key -> `{ floors, title }`) and `catalog` (wire.js maps). The roll-up of the worst state is `mount.rollup()`, in the DS's one order (`AgentOffice.worstOf`: error, waiting, review, working, finished, resting; `building.js` reads it at each call, and `test/fixtures/ds-bundle.mjs` gives the Node tests the real bundle; no copy in `vocab.js`) (room doors through `board.js` `state`, elevator buttons in the DS `FloorList`, `store.buildings()` `state` for the city windows).
- Hooks (HTTP or command) post to `/hook/http` or `/hook`. The OpenClaw office plugin posts each tool call of an office session to `/hook/openclaw` (agent token, #77): the server finds the live OpenClaw session by the Gateway key, `provider.gate` holds the call, the answer is `{ decision: 'allow' }` or `{ decision: 'deny', reason }`, and a request the plugin closes first frees the hold. `PermissionRequest` is held until `/api/answer`, or until it times out (60 s for terminal sessions, 15 min for office sessions).
- `PostToolUse`, `UserPromptSubmit` and `Stop` can return queued office messages to the session.
- The Security room rules (#70, `security.mjs`) come before every hold. The tracker's screen rates the request (`actionOf` against `rootOf(s)`, the session's agent kind, its building once placed, else the office-wide rules): Allow answers at once, Deny refuses at once with "Denied by the Security room: <row>." to the agent, Ask holds as before. Each automatic answer writes a feed line ("allowed by Security: Edit inside the worktree"), except a low call the local model asked about under its default Allow (quiet). A hook gets the answer in its reply; a provider gets it through `answer` on a later tick. Claude Code's `PreToolUse` refuses a Deny before Claude Code's own check (so its allow rules and modes cannot run it; `tracker.refuseCall` ends the call) and asks for a read or edit inside, a settings file or a secret file only when the user set that cell to Ask; `PreToolUse` never allows. A Claude Code office session (open, reopen, schedule, terminal window) opens in `default` mode while any cell the user set is Ask, and the feed says so when that overrides the asked mode. An ungated kind that is off, or a kind without cost reports set to Deny, is refused before a worktree is made (409). Every call cell is Ask by default (the local model's two inside cells are Allow), and a default cell forces nothing (review B1): for Claude Code, in terminal and office sessions alike, Claude Code decides as it did before the Security room (it reads its folder without asking), the office holds only what it asks, and the Open dialog's Permissions picker takes effect; the wall says "Partly enforced" (`enforce.unset`). One click on such a cell sets Ask, and from then on PreToolUse makes Claude Code ask. Inside the worktree means a git worktree (`s.worktree`, or a placed session whose git root holds `rootOf(s)`), never a wide root: a terminal or "Use this folder" session outside git or in the home folder has its reads and edits rated as outside. The local model is the exception (review M4): its own folder counts as inside also outside git, so its low calls run unasked there as before (never in a wide root). A session not placed yet gets the office rule unless a building has a stricter override (then held; a building's user-set Ask counts as stricter than the office default). For Claude Code, an Ask on outside files, shell, web and MCP holds only what Claude Code asks about (its own allow rules and mode decide): the wall says "Partly enforced". The rules work only while the office runs: a stopped or slow office answers no hook (the command hook gives up after its timeout, HTTP hooks do not block), and Claude Code then decides alone, also for a Deny.
- `POST /api/security/set` (page group) takes one change from the wall: `{ scope: 'office' | 'building', building, row, col, value, confirmed }`. A looser change without `confirmed: true` is 409; Allow on a Secrets row is 400. Each change writes a feed line (through `addFeed`, so the 200-line cap holds). `POST /api/settings/spend` refuses a change to No limit (0) without `confirmed: true` (409): the wall's painted Confirm sends it, and so does the Save of the Attach sessions dialog. The rules live in `state.json` (`persisted.security`), the month's cost per agent kind in `persisted.costs`. The snapshot carries `security: { rules, enforce, spend }`.
- An office session runs in its provider (`src/providers/`). The server calls `open`, `message`, `answer`, `interrupt` and `close`; the provider reports through `providerEvents` into the tracker. For Claude Code the session is `claude -p --input-format stream-json --output-format stream-json --verbose --include-partial-messages`. Messages and control requests go to stdin. Stdout messages go to `onStream()`; a control response goes back to its request in the provider.
- A provider reports in the tracker's vocabulary: hook-shaped events (`events.hook`, trimmed by `slimPayload` like the hook route), stream messages (`events.stream`), and requests it holds itself (`events.permission`). Two timing rules: a method returns before the events that follow from it (the office calls `startTurn` after `message` and `tracker.interrupt` after `interrupt`), and a provider reports nothing after `close` or `events.end`.
- A held request ends with one decision: `{ allow, always }`, `{ text }` for a question, or `{}` for none. The hold's `reply` takes it to the agent. On a hook, the session's provider gives the answer body (`claude.answer`: `hookSpecificOutput`). `POST /api/open` takes `provider` (default `claude-code`). `GET /api/providers` gives each kind's readiness, needs and models. A hold that times out says "question timed out, <provider label> moved on".
- A provider delivers `events.hook()`'s return value (queued office messages: `additionalContext`, or `decision: block` on Stop) to its agent. ACP has no way to add text to a turn that runs, so the ACP provider sends a message that came back on a tool result as the next prompt of the same turn, or with the next prompt when the turn was stopped.
- A provider frees a hold its agent no longer waits for with `events.drop(s, id, why)` (the server's `releaseHold(id, {})`); the feed says why.
- An ACP session: the office starts the agent (`src/providers/acp.mjs`), sends `initialize` with the client capabilities `fs` (read and write) and `terminal`, then `session/new` with the session folder (or `session/load` on Reopen when the agent said `loadSession`). Prompts are `session/prompt`; the agent's updates, permission requests, file calls and terminal calls come back on stdout. The office answers every `fs/*` and `terminal/*` call itself, in the root only.
- Cost unknown (owner decision Q22): a provider with `cost: 'unknown'` (the ACP agents) opens and reopens only with `confirmCost: true` while its Security room cell "Run without cost reports" is Ask (`security.costAsk`); Allow opens it with no question, Deny refuses it (`openRefusal`, before the question). Without it `/api/open` and `/api/reopen` answer 200 `{ confirm: 'cost', question: 'This agent does not report cost. Run it?' }` (no `uid`: a normal question, not an error, so the page logs no failed request; `api()` in office.js turns it into the same rejection a 409 gives) before any worktree or session; the Open dialog, a room's Add agent and Past sessions ask with `CostDialog` (office.js) and send the call again. Such a session has `costUnknown: true` (in `SESSION_FIELDS` of `public/wire.js`, `history.json`, the past list), no spend limit (`spendLimitFor` gives null: nothing could stop it), and every cost surface reads "unknown" (`OfficeFormat.cost`, `figures().unknown`), never $0.00.
- Ungated agents (ADR 0001, `traitsOf(p).gated`): `/api/open` refuses one with 409 unless this open gives it a room of its own (#69: not `isolation: 'same'` (Use this folder), not a terminal window, a folder in git; a room's Add agent does not offer it), and `/api/reopen` refuses one whose past record has no worktree (`ownRoomOnly` in `server.mjs`), both before the cost question. Its sessions carry `supervision` (the label), the cost question and the start feed name it. The switch that keeps an ungated kind off until the user turns it on is the Security room's Agents screen (#70).
- Past sessions record `provider` and `model`. Reopen calls `provider.learn()` when the provider has it, then follows `providers.reopenPlan(rec)`: a provider with `canResume` continues the conversation and the record leaves the past list; any other provider opens a fresh session in the same folder with the same model, the feed says "A new session started. This agent kind cannot resume a past session.", and the record stays. A provider that planned to resume but started a new conversation reports `events.fresh` before the sid: the record stays and the new session drops the copied replies and cost (`freshReopen`). A record with no `provider` is Claude Code's.
- Every state change calls `broadcast()`. Changes within 100 ms go out as one message. A page gets the lean snapshot whole when it connects, then one patch per broadcast (`public/wire.js`); `store.receive` applies it, and a patch that does not fit makes the page connect again. When the page starts to read a new session field, add it to `SESSION_FIELDS`, or the page never gets it. Full data of one session (sid, budget, every reply, its feed lines) is `GET /api/session?uid=`; tests and scripts read that, not `/events`. The page reads it too, for the older replies the snapshot left out (#80): a bot with `olderReplies > 0` holds the rest of its pass (replies, status, end, error) until the store has the whole list (one request per session, kept for the page; `createStore({ fetchReplies, onProblem })`, wired in `adapter.js`), then tells the replies oldest first, restored with no bubble, and the error or the end after them. A bot seated again during the wait keeps how its replies and its error are told (an old error is never news). A reply that arrives during the wait speaks, and so does a failure that arrives during it (`errTop`, the error id when the wait began; an error above it is live). A failed request, or one that gets no answer in 15 s, shows the newest replies and one error toast (`facade.onProblem`); a new scene tries again, so a failure that stays adds one toast per building change.
- Sessions are keyed by `uid`. `sid` is the agent's session id (Claude's for Claude Code). `officeId` links hooks to a session the office opened (env `OFFICE_ID`).

- Remote access (#133, ADR 0008). The server still binds 127.0.0.1; cloudflared on the PC forwards to it and the office never starts or configures it. `auth.gateRequest` is the gate (async: the key list may need a read). Remote requests need `Cf-Access-Jwt-Assertion` on every route (403 without), then the page group also needs the remote page cookie (`REMOTE_PAGE_TOKEN`, its own secret, new at each start: a remote cookie opens nothing on the local host and the local token nothing remotely). `POST /remote/signin` gives the cookie (`Secure`, `Max-Age` and `Expires` of the token) and writes a feed line and the log line `Remote sign-in: <email>`; `public/adapter.js` calls it on https when `/api/auth` answers 401. `GET /api/info` carries `remote: { state: off | on | incomplete, host, missing, reason }` (never the audience tag or the emails); the Attach sessions dialog shows `OfficeFormat.remoteNote`. Tests start copies with `OFFICE_REMOTE_CERTS_URL` (loopback http only) at a stand-in key list, and `startOnFreePort(..., { envFor })` names the port in `OFFICE_REMOTE_PORT`.
- Access (owner decision on #27 H1, rules in `auth.mjs`). Two tokens, each for one route group, neither opens the other:
  - Agent token: `/hook`, `/hook/*`, `/mcp/*`, in `x-office-token`. Kept in the token file of the office's port (`.office-token` on 4317, `.office-token-<port>` elsewhere; `{ token, port }`, read by `hook.mjs` and `mcp.mjs`) and in its HTTP hooks file. Reused across restarts.
  - Page token: `/events`, `/api/*`, in the page cookie `ao_<port>` (HttpOnly, SameSite=Strict, Path=/, no expiry date) or in `x-office-token` from the user's own tools. New at each start. ## Gotchas learned the hard way

- `OFFICE_OLLAMA_URL` and `OFFICE_LMSTUDIO_URL` move the local providers to another server on loopback. `createLocal` refuses any host that is not loopback, and then the office stops at start. The tests use them to point at the fake server (`test/fixtures/fake-openai.mjs`).
- The local provider sends only `model`, `messages`, `tools`, `stream` and `stream_options`, by POST to `/chat/completions`. LM Studio can run its own MCP servers (for example run-command) when a request names them. Never add a field or call another endpoint: a tool call could then skip `riskOf` and the approval check. `test/local-provider.test.mjs` fails on any other key or path.
- Route tests run in process: `startInProcess({ dir, env, state })` of `test/fixtures/office-inproc.mjs` builds the real office (`office.mjs`) and gives `call(route, body?)`, `hook(body, signal)` and `snapshot()` over `core.handle`. It sets the environment the office reads (home, rate file, explainer off) before it imports the office, takes an optional saved `state` the office finds at start, and keeps the office from owning its port, so it writes no file and the response is a copy, as the wire gives. One office per test process. Use it for any test that needs no gate, no body parsing, no file written at listen and no spawned program; the tests of the gate (`auth.test.mjs`), static files, branch ports, start-up files and the paid smoke run stay on real HTTP.
- A test that starts `server.mjs` copies the code to a temp folder first, with `copyOffice(dest)` of `test/fixtures/office-server.mjs` (package.json, launch.ps1, `src/`, `public/`; `{ components: true }` adds `components/` and `tokens.css`, as `test/static.test.mjs` needs; never a file list of your own): the copy has the layout of the repository, so its `OFFICE_ROOT` is the copy and the server writes its state, hook files and token file into its own folder. It also sets its own `OFFICE_PORT`, `LOCALAPPDATA` (the page file goes there; the test reads the page token from `auth.pageFile(env, port)`) and `OFFICE_OPEN=0` (no browser). A free port is never 4317, so the test finds or seeds the office's files with `officeFiles(copy, port)` (`files.mjs`), never by the plain names.
- Files a second office writes (#100): an office in a folder where another office runs, on another port (`OFFICE_PORT=<n>`, `npm run start:branch` in the main checkout), writes only its own files, with its port in the name (`files.mjs`). It never rewrites the plain files of the office on 4317, so the owner's hooks keep going to 4317, and it never loads the owner's `state.json`, so it never runs the owner's schedules or saves over the owner's notes. Its settings pass the port to `hook.mjs` and `mcp.mjs`. The only file it reads from the plain set is `.office-token`, and only when that file names its own port (an office from before #100): then it keeps that agent token, so the settings files that office made still work. A copy that stops on a busy port writes nothing. Do not add a file to the office folder outside `officeFiles`, and rate any new token or settings name in `risk.mjs` for every port (`test/risk.test.mjs` checks the `officeFiles` names).
- There is no dock (#92). `--strip-clear` is a fixed value per width in `office.css` (above the DS broadcast bar and log lane); the DS chat, roster, Since you left card, the page panels and the toast stack use it as their bottom edge. Do not hard-code another bottom offset for them. The dock's actions live in the scene (open desks, the reception memo), in the Reception dialog (`officeActions`, so a touch screen reaches them) and in Ctrl+K.
- The scene height is `office.js` state (`win.h`): a resize renders the page again, and the DS sets the new inline height. Do not override the `.ao-office` height in CSS (#55).
- At 820 px and below the room card waits while the DS Since you left card shows (`onSinceYouLeft` sets `syl`), because both sit at the bottom (#66). The lobby tour card sits at the top (at the bottom below 820 px) and is a cover for framing (`COVERS`) and for the toasts (`KEEP`).
- The page toast stack (`.page-toasts`) is placed by one rule at every width and window height: `OfficeToasts.place` (`public/toasts.js`), fed by `office.js`, which measures the boxes and sets `--toast-x`, `--toast-bottom` and `--toast-room` on the stack. It never covers a `KEEP` box (top controls, floors card, zoom column, dock and More list, every request bar `.asks`, panel head and message box, the chat's Approve and Decline (`.ao-act`) and composer, the decisions inbox, the city controls). It covers an `AVOID` box (DS HUD boxes, the panels, the welcome card) only when no band is free of it. A request bar can sit anywhere and grow: it is measured, cut by its scrolling parents, never assumed. With no band of 40 px the stack waits out of sight (`is-off`) and its clocks wait. Add a new box to `KEEP` or `AVOID` in `office.js`; do not write a `left`, `top` or `bottom` rule for `.page-toasts` (`test/toasts.test.mjs` fails on one). The Ctrl+K palette (`.ao-cmdk-o`) is one layer above the stack.
- One panel at a time: `office.js` adds `has-panel` to `#office` while a pinned screen (the desk screen, the changes on the wall), the board or the stats panel is open, and `office.css` hides `.ao-hud-right` (the DS chat and roster) then. Every such panel must show `RequestBar`, or an approval could hide behind the hidden chat. Every screen in focus shows the bezel count (`Bezel`, every request of every building; one click goes to the desk of the oldest).
- Never hide a DS right column (`.ao-hud-right`) with `display: none` above 820 px. Use `visibility: hidden; pointer-events: none`. The DS camera reads that column's left edge to frame the scene, and it does not measure again when a page class goes away, so a collapsed box frames the room small and off to the left.
- Pinned screens (#89): a target's `look` spec with `pin: true` is a screen whose look is its use. `panels.js` defines `DeskScreen` (chat from `office.chatOf`, Terminal and Timeline tabs; the requests are on the desk, desk.js) or `changes.js` `Changes.Screen` (`office.js` renders them) over `host.layer().rect`, set as `--pin-*` with `setProperty` (`putBox`), never a style prop or attribute (the CSP). The page renders again only when the layer's screen, state or count changes. The face is opaque, so the painted screen does not show through. The terminal side panel is gone; the changes dialog is left only for a session with no room on screen. The same for a Security room screen in focus at 820 px and below: `sec-look` (set in a layout effect) hides `.ao-hud-left` and `.ao-hud-right` (not the inbox), and the look bar shows the open requests (`LookBar` `asks`) and places itself again (`layout`).
- "Always allow" and the risk of a request come from `OfficeVocab.alwaysOffer / requests`. A question has no risk and no rule. A high-risk request never offers Always allow.
- Past sessions: `history` also holds open sessions (a crash must leave a resumable record), but `pastInUse()` counts a session that is open now as in use. `pastShown()` (the history route, search) and the Reopen guard use that one rule, so an open session shows once, as live, and ends up past.

The page listens with `host.onFocus`: a look shows the look bar and closes the panels; `refit()` runs when a side panel opens, the dock changes height or the window resizes.

- Every program the office runs in a room must go through the record in `git.mjs` (`git()` or `recorded()`), or a removal cannot wait for it: on Windows the room is the program's current folder, and deleting it fails with "Permission denied". Do not call `run()` or `execFile` with a room as `cwd`. A lookup in a room that is being removed waits for the removal.
- Two worktrees on one branch need `git worktree add --force`.
- Room boards are matched to rooms by order: the shown floor's lab rooms, left to right (`OfficeSceneHost` `host.rooms()`), against the chalkboards (4 x 2.5 planes). The engine rebuilds a floor when a bot joins or the theme changes. The host sees that (new bot list, floor, floor groups, theme tokens, or a lost anchor) and fires `onRebuild` before the frame draws; board.js and terminal.js rescan then, and still on a 1.5 s timer.
- Only `public/scene-host.js` reads the DS stage's floors, views and room geometry. A new painted screen is one `host.screen(spec)` call (target, rebuild, frame, tick) plus its paint; a decoration with no screen registers a frame (`host.frame`) alone. Do not add a pick Raycaster (one that turns the pointer into an action), pointer listeners or `canvas.style.cursor` writes in another file: two raycasts gave two actions for one click. Geometry raycasts that do not react to the pointer, like terminal.js placing the desk light, are fine. The building view is `host.inBuilding()` (no floor group is visible), not the Building button's `aria-pressed`.
- The scene fades out (`duration-base`) before any rebuild: another building, the city, a removed floor or room. Labels in the city sit on layer 1 so the bloom pass skips them.
- Extensions: `mcp_status`, `mcp_toggle`, `mcp_reconnect`, `reload_plugins` are control requests on the session's stdin; they work before the first prompt. Persistent changes use `claude mcp` and `claude plugin` with scope local or project only.
- A trackpad flick sends wheel events for about a second, some after the finger lifts. Scroll-out goes through `OfficeWheelGate`: events less than 140 ms apart are one gesture, and a gesture that changed a level changes no more. Do not count scroll-out wheel events by hand (`city.js` counts zoom-in pushes to enter, which is a different gesture). While the gate holds, `office.js` stops the wheel event so the DS camera feel does not clear the framing.
- A status word on a theme surface (bg, panel, chip) is `--status-*-text` with a dot in `--status-*` (`::before`); on a bubble face it is `--status-*-on-bubble`. A raw `--status-*` is a fill or a dot: it is not 4.5:1 as text in Day. The terminal (the desk screen's Terminal tab) is a `scene-dark` face, where neither text token reads, so its tones mix the status color into `bubble`. `test/contrast.test.mjs` computes the pairs from `tokens.json` and fails on a rule that colors text with a raw `--status-*` outside the pinned mixes. A word that marks something other than a status (a hot file, a building that needs you) stays ink. The DS checker rejects custom properties that are not DS tokens, so write the value in the rule.
- The notes editor and the City label sit on light faces in every theme (bubble, chip). Their ink is the mix `board.js` uses, not `--ink` (light at night). The City label card is the `bg` color (the DS `K.tok` has no `chip` or `line`).
- The City's minimum zoom is Show all (`SHOW_ZOOM` times `s.D` over the fit distance), set every frame in `city.js`. Do not set `ctl.minZoom` to a constant.
- Reduced motion in the 3D scripts: `stage.rm` is read when the stage is made. The DS engine cuts every camera move under reduced motion (`stage.goal` ends on its first step), so `city.js` passes no reduced-motion flag to `stage.frame`. The page's own motion still reads `stage.rm`: city zoom steps and tweens are instant, a building lifts at once, a flight to a room screen and back lands in one frame (`scene-host.js`), the door stays shut and shows a still ring (`d.ring` in `board.js`), terminal cursors are solid (`terminal.js`). The DS engine's own camera moves are the DS's.
- Start every program with `resolveExe(name)` from `launch.mjs`, never a bare name. On Windows a bare name is looked up in the child's folder first, so a planted `git.exe` in a repo would run. The entry points also set `NoDefaultCurrentDirectoryInExePath`. `test/spawn-safety.test.mjs` scans the sources for bare names.
- `git.locate` tries a passing git failure (a time limit on a loaded machine, a lock) 3 times before it answers null. Null means "not in git" and the office acts on it, so never let one slow git call give it (#98). The office start reads its recent folders and its branch with `git.locateOrKeep`, which answers `KEEP` after the last try. A lasting failure (not a repository, a folder git refuses for its owner, no git) is null at once and is not tried again: `run` keeps only the last 3 lines of git's message, so the dubious-ownership check also matches `safe.directory`.
- Tests that run a real `server.mjs` copy start it with `test/fixtures/office-server.mjs` (`startOnFreePort`, `startOffice`), never with their own `spawn` and `freePort`. Ready is the server's own "is open" line, which comes after the files are written; the wait is 240 s but a server that exits first fails at once with its output. A free port can be taken before the server binds it, so `startOnFreePort` starts again on a new port when the server says it is busy; files that carry the port in their name (`officeFiles(dir, port)`) are made in its `prepare(port)`. `OFFICE_PORT=branch` tests move the branch name instead (`git branch -m`), because the port comes from the name (#98).
- The Bash tool mangles backslashes and quotes in long heredocs. Write patch scripts with the Write tool.
- A test that makes a temp folder removes it in a `finally` block (or, for a rig that many tests share, in the file's `after()` list as `floors.test.mjs` and `acp-provider.test.mjs` do). `npm test` loads `test/fixtures/temp-leaks.mjs` in every test process: a process that ends with a temp folder still there is removed, named on stderr, and fails (#124). It wraps `fs.mkdtempSync`, `fs.mkdtemp` and `fs.promises.mkdtemp` (and syncs the ESM named exports), so a named import is caught too. To count leaks by hand, run the suite with a private `TEMP` and read the folder after.

## Safety rules

- The Security room rules decide before any hold, and a looser rule never applies without its painted Confirm (the route refuses it). The two Secrets rows never take Allow. A cell the office cannot enforce for an agent kind must say "Not enforced" with the reason, an Ask the agent decides by itself "Partly enforced" with the reason, and a row where only some calls reach the office (Hermes: edit requests do, reads and its own skill and memory writes do not) "Partly enforced" too, with `partly` of `enforcement()`: never show a rule as active when it is not (ADR 0001). The rules apply only while the office runs; say so wherever enforcement is described.
- Bind to 127.0.0.1, check the Host header and the Origin, and require the token of the route's group on every route except the page, its static files and `POST /launch` (which takes a one-time launch code). The agent token never opens `/api/*` or `/events`; the page token never opens `/hook*` or `/mcp/*`. A new route goes into one group in `auth.routeOf`.
- Never edit `~/.claude/settings.json` or `.credentials.json`. The office only writes files in this folder, its page file in `%LOCALAPPDATA%\AgentOffice`, and the per-project rule a user approves. Opening an agent also writes `branch.<agent branch>.officebase` into the repository's `.git/config` and makes the folder `<repo>.worktrees` and the worktrees in it (next to the repository, outside this folder). The key only places the room on a floor and is display-only: an agent can edit it and so choose the floor of its own room, and nothing else reads it. The office never removes these worktrees or branches by itself, except the worktree and branch of a fork that did not start (`git.discardNew`, see the rule on pull requests below).
- Paperclip runtime (ADR 0010, #193): the office installs only the pinned `paperclipai` (exact version, no install scripts, SHA-512 checked against npm's lock file) into `.paperclip-runtime`, never over a Paperclip that already answers on the port, never into or over `~/.paperclip`; it starts Paperclip only in login mode on 127.0.0.1 (a health answer in another mode stops it), with a scrubbed environment (no `PAPERCLIP_*`, `DATABASE_URL`, `HOST` or `PORT` of the owner) and its own instance, data folder and database port; it kills only a process it started or adopted by pid and start time. The board key and Paperclip's first-run secrets are written with `writeSecret` only (owner-only) and never reach a page, a feed line, a reason or an error. The first admin and the key approval are a person's steps: the office never makes an account. The rest of this rule (ADR 0005) is the HQ until its tickets (#191) rebuild it.
- Paperclip (ADR 0005): watch only, loopback only (127.0.0.1, no redirect, no secret kept), off until the user connects it. The office never sends heartbeats, assigns tasks, runs routines or changes budgets. Its one write is Supervise in office: one PATCH of one agent's adapter config, only after the painted Confirm on the Agents screen (the route refuses it without `confirmed: true`). An agent shows Unsupervised until Paperclip's saved config carries all three settings; never show it as supervised from what the office sent. A flag or an env key that lets a run approve its own calls or turns off hooks is never supervised; a flag or env key that loads what the office cannot read, a flag it does not know and another program than claude are Partly supervised (ADR 0001: never show Supervised while a call can skip the hold). Supervise builds its PATCH from the agent as Paperclip has it at the click, never writes env, and shows the agent as Paperclip saved it after the PATCH.
- Extensions change only the local or project scope of a session's folder. User scope stays out of reach, also through `claude mcp` or `claude plugin` (owner decision, 2026-11-03).
- Nothing is answered for the user unless a cell the USER set says Allow or Deny (the defaults are built, 2026-11-05: Claude Code decides on default cells, and `~/.claude` and `~/.hermes` are always settings paths; an OpenClaw session starts only while its Gateway config loads the office plugin for this office (#77); the owner may change them). Every call cell of every agent kind is Ask by default, a low-risk read or edit inside a worktree included, in terminal and office sessions alike. A default cell also forces no prompt (review B1): Claude Code decides what it asks, as before the Security room, and only a cell the user set makes it ask or changes its permission mode. The one exception is the local model: its reads and edits in its folder never were requests (they ran at once in `src/providers/local.mjs`, also in a folder outside git), so its two inside cells default to Allow and show it on the wall. A gated provider holds every tool call until the user answers or a user-set cell answers it. Only a provider with `gated: false` skips the hold (owner decision, 2026-11-04, `docs/adr/0001-ungated-agents.md`). An ungated agent shows "Unsupervised" or "Partly supervised", is off until the user turns it on in the Security room, and runs only in a fresh worktree. A setting the office cannot enforce for an agent shows "Not enforced for this agent". The Secrets cells never offer Allow, and ACP agents never get Always allow.
- Pull requests, pushes and worktree removal happen only after an explicit click and a confirm dialog. One exception: a fork that did not start (it ended before init, or its open threw) removes the worktree that the same call made for it, which never held work (`failedFork` and the catch in `forkSession`). It goes through `git.discardNew`, which takes only the object `createWorktree` returned in this process, once, and does not force: a copy (a past record, a session's `worktree` field) is refused, so no other worktree can be removed this way. Tested in `test/floors.test.mjs`.
- Do not add dependencies without asking. The server runs on Node built-ins. The page loads nothing from another site: React and the fonts are vendored in `public/vendor` (owner decision on #27 M2), and the CSP allows scripts, style sheets and fonts from the office only.
- A remote image in agent text loads only after the user clicks it (DS RichText). `data:` and `blob:` are the only images that show at once.
