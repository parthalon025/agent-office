# Development

How the office works inside, which files do what, and how to run and test it. [CLAUDE.md](../CLAUDE.md) has the module map, one line per file. The rules a module owns are in the header comment at the top of that file, and [How data moves](#how-data-moves) below says how the modules work together. The design system documents are in [DS-README.md](design-system/DS-README.md).

## Commands

```
npm start            # the server on 127.0.0.1:4317; prints and opens a one-time launch link
npm run start:branch # the server on the port of this checkout's branch (4330-4399); prints the link and opens nothing
npm run probe        # prove HTTP hooks on this Claude Code version (one tiny call)
npm run smoke        # open real Haiku sessions in a throwaway repo (a few cents); the office must be running
npm run gate:jobs    # count the steps of the five core jobs in a headless browser (no paid call)
npm test             # offline tests
npm run test:junction # Windows: the room and floor tests with TEMP behind a junction
npm run check:merge  # the merge checklist in one run (see below)
```

- `npm test` passes a quoted glob to `node --test`, which Node reads only from version 21 on. The office needs Node 24.11 or newer (the minimum of Paperclip). `src/node-check.mjs` stops an older Node at start.
- `npm run probe -- <port>` and `npm run smoke -- <port>` test an office on another port.
- `npm run gate:jobs` is not part of `npm test` and not in CI. It needs Chrome or Edge, starts its own office on a free port (never 4317), seeds it with fake hooks, and fails when a job takes more steps than its limit. The five jobs are start an agent, answer an approval, read the change, discard a room and find a past session. Its screenshots go to `.screens/core-jobs/` and are never committed. Run it before a UI merge.
- Before you finish a UI change, run the design system checker:

```
python kit/check.py public/index.html public/office.css public/page-core.js public/skills.js public/dialogs.js public/schedules.js public/extensions.js public/hq.js public/characters.js public/reception.js public/panels.js public/changes.js public/screens.js public/merge.js public/needs.js public/office.js public/adapter.js public/chat-extras.js public/city.js public/board.js public/terminal.js public/persona.js public/lobby.js public/desk.js public/wheel-gate.js public/vocab.js public/ask.js public/client.js public/screen-kit.js public/scene-host.js public/building.js public/format.js public/toasts.js public/wire.js public/security.js public/vocab-security.js public/vocab-layers.js public/vocab-persona.js components/bundle.css components/bundle.js kit/page.html
```

The list is the one of the `kit/check.py` step in `.github/workflows/ci.yml`; `test/ds-kit.test.mjs` checks that this command and the one in `CLAUDE.md` name the same files.

## The Paperclip contract

The office pins one Paperclip release (`PINNED` in `src/paperclip-runtime.mjs`). Check every Paperclip route, body key and word against that release, never against a guess or a newer source tree.

```
npm run paperclip:source     # downloads the pinned release into .paperclip-source/ (git-ignored, about 11 MB)
node --test test/paperclip-contract.test.mjs
```

`test/paperclip-source.mjs` fetches three packages from the npm registry: `paperclipai` (checked against the SHA-512 in `PINNED`) and its two exact-version dependencies `@paperclipai/server` and `@paperclipai/shared` (their SHA-512 are pinned in the same file). It checks each hash before it extracts anything, keeps only the routes, the realtime socket, the validators and the types, and runs no npm and no install script. It does nothing when the right version is already there. When you move the pin, add the two new hashes (`npm view @paperclipai/server@<version> dist.integrity`).

Read the routes in `.paperclip-source/server/dist/routes/*.js` (`router.get("/path", validate(someSchema), ...)`; `app.js` mounts them under `/api`; `health.js`, `companies.js` and `auth.js` have their own prefix) and the validators in `.paperclip-source/shared/dist/validators/`.

`test/paperclip-contract.test.mjs` checks that every route the office sends or reads (`paperclip.mjs`, `hq-model.mjs`, `paperclip-runtime.mjs`, the write kinds in `src/hq-writes/`) and every route the stand-in `test/fixtures/fake-paperclip.mjs` serves exists in the release, that the body keys of the sample of every write kind action are keys of the validator on that route, that the enum words the office writes (roles, statuses, levels) are words of the release, and that the answers it reads have the fields it expects. A new Paperclip write is a write kind (one file in `src/hq-writes/`, listed in its `index.mjs`) with a sample for each action: `test/hq-writes.test.mjs` checks each sample (the exact request, byte for byte, and the ids returned), and the contract test picks the samples up. Without `.paperclip-source/` the test is skipped with the command above, so a run with no network passes. CI runs `npm run paperclip:source` on the Linux job before the tests, so the contract holds there.

## Test guards and the merge check

- `test/fixtures/temp-leaks.mjs` (loaded by `npm test` in every test process) fails a process that leaves a temp folder, a room under `OFFICE_ROOMS_DIR`, a new entry under the real `~/.agent-office`, or a new entry under the real `%LOCALAPPDATA%\AgentOffice` (page files, Paperclip data folders, board key files). A test must point `LOCALAPPDATA` at its own folder.
- `npm run test:junction` (Windows only) runs the room, floor, campus and place tests with `TEMP` and `TMP` behind a junction to a fresh folder, as on GitHub's Windows runner, where TEMP is an 8.3 short path. It removes the junction after.
- `npm run check:merge` runs the merge checklist and prints one line per step: `node --check` on the files changed against the merge-base with `origin/main` (`--base <ref>` to change it), `kit/check.py` with the file list read from `.github/workflows/ci.yml`, `npm test` twice, `test:junction` and `gate:jobs`. It exits 1 when any step fails and takes about 5 minutes. Linux is left to the ubuntu job of CI.

## Branch ports

`OFFICE_PORT=branch` (and `npm run start:branch`) takes a port from the name of the current branch, in the range 4330-4399, so each worktree has its own office. The name gives a fixed sequence of 12 ports. The office takes the first free one and prints which one it took. Final browser tests of a worktree run on that port and never on 4317, which is the port of your own office. Stop an office by the process id that owns its port (`netstat -ano | findstr :<port>`, then `taskkill /PID <pid> /F`). Never stop one by image name: that would stop your other Claude Code sessions. The full rule is under `OFFICE_PORT` in [Configuration](configuration.md).

## How it works

```
Claude Code ──hooks (HTTP or command)──▶ src/server.mjs ──SSE──▶ browser (adapter.js ▶ Agent Office DS)
     ▲  ▲                                   │  │
     │  └── stdin: messages, control ───────┘  └── REST: open, close, answer, message, history ...
     └───── MCP (src/mcp.mjs): office_inbox, office_ask, office_room, office_room_update
```

- **Hooks** report prompts, tool calls (with their id and time), failed tool calls, subagent start and stop, and stops. `payload.mjs` trims each payload the same way for command and HTTP hooks; tool output never leaves the session. A `PermissionRequest` hook holds the prompt until you answer in the office.
- **Sessions in the office** run `claude -p` in stream-json mode with a pipe. Messages go in on stdin, replies and control requests come out on stdout.
- **MCP** gives a session four tools: read messages the user sent from the office, ask the user a question, describe its room (`office_room`), and change the room's notes board or blackboard pin when the user asks (`office_room_update`).
- **The adapter** (`public/building.js`, loaded by `public/adapter.js`) turns the server's session snapshots into design system events. A snapshot store holds the latest snapshot, and each mounted building has its own adapter.

### Hook modes

The office uses **HTTP hooks** when they were proven on your Claude Code version, which makes each event about 60 times faster than starting Node. Otherwise it uses **command hooks**. Run `npm run probe` after a Claude Code update to test HTTP hooks again. A stopped office never blocks Claude, because HTTP hook failures are non-blocking and command hooks always exit 0.

## How data moves

What crosses modules. The rules of one module are in the header comment at the top of its file; this section is how the modules work together. In this section a bare `x.mjs` is `src/x.mjs`.

### Hooks and holds

- Hooks (HTTP or command) post to `/hook/http` or `/hook`. The OpenClaw office plugin posts each tool call of an office session to `/hook/openclaw` (agent token, #77): the office finds the live OpenClaw session by the Gateway key, `provider.gate` holds the call, the answer is `{ decision: 'allow' }` or `{ decision: 'deny', reason }`, and a request the plugin closes first frees the hold. `PermissionRequest` is held until `/api/answer`, or until it times out (60 s for terminal sessions, `OFFICE_ASK_TIMEOUT_S`; 15 min for office sessions).
- `PostToolUse`, `UserPromptSubmit` and `Stop` can return queued office messages to the session.
- A held request ends with one decision: `{ allow, always }`, `{ text }` for a question, or `{}` for none. The hold's `reply` takes it to the agent. On a hook, the session's provider gives the answer body (`claude.answer`: `hookSpecificOutput`). `POST /api/open` takes `provider` (default `claude-code`). `GET /api/providers` gives each kind's readiness, needs and models. A hold of an office session that times out says "question timed out, <provider label> moved on"; a terminal session's says "question went back to the terminal".

### The Security room before a hold

- The Security room rules (#70, `security.mjs`) come before every hold. The tracker's screen rates the request (`actionOf` against `rootOf(s)`, the session's agent kind, its building once placed, else the office-wide rules): Allow answers at once, Deny refuses at once with "Denied by the Security room: <row>." to the agent, Ask holds as before. Each automatic answer writes a feed line ("allowed by Security: Edit inside the worktree"), except a low call the local model asked about under its default Allow (quiet). A hook gets the answer in its reply; a provider gets it through `answer` on a later tick.
- Claude Code's `PreToolUse` refuses a Deny before Claude Code's own check (so its allow rules and modes cannot run it; `tracker.refuseCall` ends the call) and asks for a read or edit inside, a settings file or a secret file only when the user set that cell to Ask; `PreToolUse` never allows. A Claude Code office session (open, reopen, schedule, terminal window) opens in `default` mode while any cell the user set is Ask, and the feed says so when that overrides the asked mode.
- An ungated kind that is off, or a kind without cost reports set to Deny, is refused before a worktree is made (409).
- Every call cell is Ask by default (the local model's two inside cells are Allow), and a default cell forces nothing (review B1): for Claude Code, in terminal and office sessions alike, Claude Code decides as it did before the Security room (it reads its folder without asking), the office holds only what it asks, and the Open dialog's Permissions picker takes effect; the wall says "Partly enforced" (`enforce.unset`). One click on such a cell sets Ask, and from then on PreToolUse makes Claude Code ask.
- Inside the worktree means a git worktree (`s.worktree`, or a placed session whose git root holds `rootOf(s)`), never a wide root: a terminal or "Use this folder" session outside git or in the home folder has its reads and edits rated as outside. The local model is the exception (review M4): its own folder counts as inside also outside git, so its low calls run unasked there as before (never in a wide root).
- A session not placed yet gets the office rule unless a building has a stricter override (then held; a building's user-set Ask counts as stricter than the office default).
- For Claude Code, an Ask on outside files, shell, web and MCP holds only what Claude Code asks about (its own allow rules and mode decide): the wall says "Partly enforced".
- The rules work only while the office runs: a stopped or slow office answers no hook (the command hook gives up after its timeout, HTTP hooks do not block), and Claude Code then decides alone, also for a Deny.
- `POST /api/security/set` (page group) takes one change from the wall: `{ scope: 'office' | 'building', building, row, col, value, confirmed }`. A looser change without `confirmed: true` is 409; Allow on a Secrets row is 400. Each change writes a feed line (through `addFeed`, so the 200-line cap holds). `POST /api/settings/spend` refuses a change to No limit (0) without `confirmed: true` (409): the wall's painted Confirm sends it, and so does the Save of the Attach sessions dialog. The rules live in `state.json` (`persisted.security`), the month's cost per agent kind in `persisted.costs`. The snapshot carries `security: { rules, enforce, spend }`.
- What a provider's own config enforces: the office reads `provider.policy()` (`refreshEnforce` in `office.mjs`: at listen, after a rule change, when the page asks for the kinds), and `security.enforcement(providers, policies)` marks each cell whose setting is off or unreadable "Not enforced for this agent" with the reason (OpenClaw's Gateway config, `openclaw.mjs`).
- All four ACP tools (gemini, opencode, kimi, acp) share the one Security room column `acp` ("ACP tools", `public/vocab-security.js`); with #217's `cli` column the grid has ten columns (label column 134 px, row labels wrap, head type down to 16 px, a two-word head takes a line a word, a cost word of two parts wraps on the Spend screen, a fifth reasons level).
- Earned trust (#153, `trust.mjs`): routes `/api/trust/apply|withdraw|dismiss` (page group, in `office.mjs`); the snapshot carries `security.trust`; the page is `Hq.Trust` in `public/hq.js` (Ctrl+K Earned trust).

### Agent sessions and providers

- An office session runs in its provider (`src/providers/`). The office (`office.mjs`) calls `open`, `message`, `answer`, `interrupt` and `close`; the provider reports through `providerEvents` into the tracker. For Claude Code the session is `claude -p --input-format stream-json --output-format stream-json --verbose --include-partial-messages`. Messages and control requests go to stdin. Stdout messages go to `onStream()`; a control response goes back to its request in the provider. A headless session emits `init` (session id, commands, skills) only after its first message, so the office keeps the last command list (`record('commands')`) for new sessions.
- Before the cost question and before a worktree, the office asks the provider's `preflight()` (OpenClaw: 409 "OpenClaw cannot start: ...").
- Agent kinds (#20): the snapshot carries `kinds` (`src/providers/index.mjs describe`: label, paid, terminal, modes, needsModel, control) and each session its `provider`. The page shows a kind's options and its word (`OfficeVocab.kindWord`, `officeAdapter.kindWord`) from them; readiness and models come from `GET /api/providers`. The kind rules of the forms (state word, model choices, first model, a kind change, the note) are `OfficeVocab` functions too, tested in `test/vocab.test.mjs`. The HUD connection name is `mount.agentName()` (the kinds of the building's open sessions), read through a getter on the DS adapter's `name`. Do not write a provider rule into the page: add a fact to `describe()`.
- Cost unknown (owner decision Q22): a provider with `cost: 'unknown'` (the ACP agents) opens and reopens only with `confirmCost: true` while its Security room cell "Run without cost reports" is Ask (`security.costAsk`); Allow opens it with no question, Deny refuses it (`openRefusal`, before the question). Without it `/api/open` and `/api/reopen` answer 200 `{ confirm: 'cost', question: 'This agent does not report cost. Run it?' }` (no `uid`: a normal question, not an error, so the page logs no failed request; the page client, `public/client.js`, turns it into the same rejection a 409 gives) before any worktree or session; the Open dialog, a room's Add agent and Past sessions ask with `CostDialog` (`public/page-core.js`) and send the call again. Such a session has `costUnknown: true` (in `SESSION_FIELDS` of `public/wire.js`, `history.json`, the past list), no spend limit (`spendLimitFor` gives null: nothing could stop it), and every cost surface reads "unknown" (`OfficeFormat.cost`, `figures().unknown`), never $0.00.
- Ungated agents (ADR 0001, `traitsOf(p).gated`): `/api/open` refuses one with 409 unless this open gives it a room of its own (#69: not `isolation: 'same'` (Use this folder), not a terminal window, a folder in git; a room's Add agent does not offer it), and `/api/reopen` refuses one whose past record has no worktree (the `ownRoom` step of `admission.mjs`), both before the cost question. Its sessions carry `supervision` (the label), the cost question and the start feed name it. The switch that keeps an ungated kind off until the user turns it on is the Security room's Agents screen (#70).
- Adapter features (#72). A provider declares `features` (`traitsOf(p).features`); the office puts `features` on each session at snapshot time (the kind's label is `kindWord` from the snapshot's `kinds`, #20; `GET /api/session` and the past list also carry `agent`, the label, for Export), and the page shows a feature only for a kind that declares it (no greyed-out controls). Routes (page group): `/api/skills/list|read|save|delete` (by agent kind; save and delete are held: 409 with `confirm: 'skill'` until the same call comes with `confirmed: true`), `/api/fork` (held the same way with `confirm: 'fork'`; a copy of a past session in a new worktree that starts from the main folder's current commit, not from the old session's changes, and the confirm text says so; for a kind that declares `fork`, which an ACP agent does only when its handshake says `sessionCapabilities.fork`; the past record stays; a fork that ends before init removes its empty worktree, `failedFork`), `/api/export` (a live or past session as Markdown; every agent kind). Search is `/api/search` over live sessions and `history.json`, for every kind. A past record keeps its last 40 calls (command and error text with keys and token values masked by `OfficeFormat.redactSecrets`) and its tokens for Export; Export masks them again. A request carries the agent's `reason` (payload `ask_reason`). `.hermes` paths are rated high by `risk.mjs`, so an agent's own skill or memory write is held.

### The snapshot and the page

- Every state change calls `broadcast()`. Changes within 100 ms go out as one message. A page gets the lean snapshot whole when it connects, then one patch per broadcast (`public/wire.js`); `store.receive` applies it, and a patch that does not fit makes the page connect again. When the page starts to read a new session field, add it to `SESSION_FIELDS`, or the page never gets it.
- Full data of one session (sid, budget, every reply, its feed lines) is `GET /api/session?uid=`; tests and scripts read that, not `/events`. The page reads it too, for the older replies the snapshot left out (#80): a bot with `olderReplies > 0` holds the rest of its pass (replies, status, end, error) until the store has the whole list (one request per session, kept for the page; `createStore({ fetchReplies, onProblem })`, wired in `adapter.js`), then tells the replies oldest first, restored with no bubble, and the error or the end after them. A bot seated again during the wait keeps how its replies and its error are told (an old error is never news). A reply that arrives during the wait speaks, and so does a failure that arrives during it (`errTop`, the error id when the wait began; an error above it is live). A failed request, or one that gets no answer in 15 s, shows the newest replies and one error toast (`facade.onProblem`); a new scene tries again, so a failure that stays adds one toast per building change.
- Sessions are keyed by `uid`. `sid` is the agent's session id (Claude's for Claude Code). `officeId` links hooks to a session the office opened (env `OFFICE_ID`).
- The scene fades out (`duration-base`) before any rebuild: another building, the city, a removed floor or room (`office.js`, `office.css`).

### Buildings, floors and rooms

- Function floors (#92): the office (`campus.mjs`) makes a building's record once from `detect(namesOf(dir))` (names only, root and one level down), the first time it knows the building (`layoutRecord`). Only `POST /api/layout { building, action, archetype?, floor?, name?, by? }` changes it (400 with the reason). Each session's seat is `seatOfSession` (in `fullSession`, `session.seat`); the snapshot carries `layouts`, `rooms` (notes key -> `{ floors, title }`) and `catalog` (wire.js maps). The roll-up of the worst state is `mount.rollup()`, in the DS's one order (`AgentOffice.worstOf`: error, waiting, review, working, finished, resting; `building.js` reads it at each call, and `test/fixtures/ds-bundle.mjs` gives the Node tests the real bundle; no copy in `vocab.js`) (room doors through `board.js` `state`, elevator buttons in the DS `FloorList`, `store.buildings()` `state` for the city windows).
- Agent rooms (#69, spec #67). An agent is a top-level session (`uid`); a subagent is a guest in its parent's room (a provider reports it with `agent_id`; the rule is in the `events.hook` note of `src/providers/index.mjs`). `POST /api/open` makes a new worktree for the agent unless `isolation: 'same'` ("Use this folder" in the open dialog); a terminal window and a folder outside git work in the folder (outside git the feed says so). The default changed with #69: a caller that omits `isolation` (API, scripts) gets a worktree. Schedules still choose their own `isolation`; a schedule with `isolation: 'worktree'` makes a new worktree and branch on every run, and the office never removes them (a follow-up: reuse one worktree per schedule). The room of an agent worktree sits on the floor of its base branch, so three agents are three rooms on one floor. Terminal sessions in one folder, or sessions with "Use this folder", share the room: the door sign (the page's sign on the room; the DS room name sign keeps the branch name, and is not ours to change) says "N agents" (`OfficeVocab.agentsSign` over `figures.sessions`, helpers do not count). The office never moves a terminal session and never removes a worktree by itself (one exception: `git.discardNew` removes the worktree of a fork that did not start; see the Safety rules in `CLAUDE.md`).
- A git room is on the floors where an agent of it sits now (owner rule, #92 review): the office keeps a record per notes key (`persisted.rooms`, `rooms.mjs settleRooms`, dropped with its worktree by `dropGoneRooms`), and a floor no agent of the room sits on leaves the record. The page side is in the header of `public/building.js`.
- `adoptNotes()` (in `office.mjs`, called from the `placed` record there; `campus.mjs` gets it injected and calls it after a room-list refresh) moves a note or pin saved under an old key (room id without hash) to the new key when its room is first seen.
- Paper flow (#93, `changes.mjs`): `campus.mjs` reads the pull requests on change events and every 30 s (`refreshChanges`) and merges (`mergeChange`); `office.mjs` puts `changes` in the snapshot and has `POST /api/merge` (the one write: 409 with `confirm: 'merge'` until `confirmed: true`, and only for a change read as ready now). `building.js changes / folderAt / requests` turn it into folders (shape, place and mark from `OfficeVocab.folderOf`, never color alone), the tray and the board; a read older than 3 minutes is unknown; Ready to merge entries count toward Needs you (kind `merge`, no uid). The page shows them in Needs you and in the Changes dialog (Ctrl+K).

### Past sessions and Reopen

- Past sessions record `provider` and `model`. Reopen calls `provider.learn()` when the provider has it, then follows `providers.reopenPlan(rec)`: a provider with `canResume` continues the conversation and the record leaves the past list; any other provider opens a fresh session in the same folder with the same model, the feed says "A new session started. This agent kind cannot resume a past session.", and the record stays. A provider that planned to resume but started a new conversation reports `events.fresh` before the sid: the record stays and the new session drops the copied replies and cost (`freshReopen`). A record with no `provider` is Claude Code's.
- Remove (Changes, `/api/worktree/remove`) sets the past record's folder to the main folder and marks it `roomGone` (branch, root); Reopen of such a record answers 409 "Its room was removed ..." and opens nothing, because it would run the agent in the user's own folder (Fork into a new worktree stays possible).
- Reopen keeps the past record until the reopened session has a `sid` (`reopening` in `office.mjs`). The tracker saves a session the moment its sid first arrives (init line or first hook), so the record swap happens then, not at the first turn end. While the reopened session is live and not ended, its past record is hidden from Past sessions and a second reopen answers 409. A reopen that ends before init keeps the record and shows Error through `tracker.fail`; a close the user asked for gives no error (#54).

### Access

Owner decision on #27 H1; the rules are in `auth.mjs`. Two tokens, each for one route group, neither opens the other:

- Agent token: `/hook`, `/hook/*`, `/mcp/*`, in `x-office-token`. Kept in the token file of the office's port (`.office-token` on 4317, `.office-token-<port>` elsewhere; `{ token, port }`, read by `hook.mjs` and `mcp.mjs`) and in its HTTP hooks file. Reused across restarts.
- Page token: `/events`, `/api/*`, in the page cookie `ao_<port>` (HttpOnly, SameSite=Strict, Path=/, no expiry date) or in `x-office-token` from the user's own tools. New at each start. Never in the office folder: in server memory, and in `pageFile()` = `%LOCALAPPDATA%\AgentOffice\office-page-<port>.json` (`{ token, port }`) for `probe.mjs`, `test/smoke.mjs` and a second `npm start`. `risk.mjs` rates a read of that file as a secret. The file has an owner (#126): a clean exit (SIGINT, SIGTERM, exit) removes it while it still holds this office's token, and the start sweeps every other `office-page-<port>.json` whose port has no listener (`probeGateway`, a loopback connect that sends nothing); `taskkill /F` runs no handler, so the sweep is what clears those. A listener that is not an office keeps its file.
- Launch code: at `listen` the server mints one, prints `http://127.0.0.1:<port>/#n=<code>` and opens it (`cmd /c start ""`, off with `OFFICE_OPEN=0`). `adapter.js` removes the code from the address bar and sends it to `POST /launch` (public, JSON, same origin). A code works once, for 5 minutes; the answer sets the cookie. `POST /api/launch-link` (page token) mints another; a second `npm start` that hits EADDRINUSE uses it and opens the new link.
- Public: `GET /`, `/favicon.ico`, the static files (`STATIC_FILES`, an exact-match map from URL path to file; the request path is never part of a file path). `GET /` holds no token.
- Remote access (#133, ADR 0008). The server still binds 127.0.0.1; cloudflared on the PC forwards to it and the office never starts or configures it. `auth.gateRequest` is the gate (async: the key list may need a read). Remote requests need `Cf-Access-Jwt-Assertion` on every route (403 without), then the page group also needs the remote page cookie (`REMOTE_PAGE_TOKEN` in `server.mjs`, its own secret, new at each start: a remote cookie opens nothing on the local host and the local token nothing remotely). `POST /remote/signin` gives the cookie (`Secure`, `Max-Age` and `Expires` of the token) and writes a feed line and the log line `Remote sign-in: <email>`; `public/adapter.js` calls it on https when `/api/auth` answers 401. `GET /api/info` carries `remote: { state: off | on | incomplete, host, missing, reason }` (never the audience tag or the emails); the Attach sessions dialog shows `OfficeFormat.remoteNote`. Tests start copies with `OFFICE_REMOTE_CERTS_URL` (loopback http only) at a stand-in key list, and `startOnFreePort(..., { envFor })` names the port in `OFFICE_REMOTE_PORT`.

### Paperclip HQ

The module rules are in the headers of `paperclip.mjs`, `hq-model.mjs`, `hq-writes/index.mjs` (the write kinds and the context the writer gives them), `paperclip-runtime.mjs`, `paperclip-runs.mjs`, `memory.mjs`, `manager.mjs` and `manager-employees.mjs`; the user side is in [Paperclip HQ](paperclip.md). What crosses into the snapshot and the page:

- The snapshot carries `hq` (`public/wire.js` lean); each session carries `hq` (`SESSION_FIELDS`), its run's label from `hq.labelOf(s.paperclip)`.
- The page: the HQ building and its row in the city (`hqBuilding` in `office.js`, first in the list), the HQ dialog (`HqDialog` in `public/hq.js`: agents, tasks, heartbeats, budgets, routines), the connect part of Attach sessions (`PaperclipConnect` in `public/dialogs.js`), the Paperclip part of the Agents screen, the bot card (`platform` "Paperclip <role>, Claude Code", `owner` company and agent, task line from `s.hq.task`) and a Paperclip row on the stats display (role and budget). The HQ phone block lists no approvals: they are items of `view().inbox` (`hq-model.mjs` `inboxOf`).
- The page decides a waiting Paperclip approval from Needs you and the HQ lobby (Approve, Reject, Request revision, optional note) through `hq.write` and the Approvals cell. A render sends nothing. The page has no write grid wall or mailroom yet: those are later tickets, and they send the routes of `hq.write`.
- Office adapter runs (#200): agent routes `POST /hook/paperclip/run/start|wait|cancel` (agent token, JSON; bodies in the header of `paperclip-runs.mjs`). `paperclip.mjs supervisionOf` calls an `agent_office` employee Supervised (`OFFICE_ADAPTER`). `transcript(uid)` gives the log of a run by its office session (live or kept), the session carries `paperclipRun: true` (in `SESSION_FIELDS`), and `GET /api/paperclip/transcript?uid=` (page group; 404 for a session that is not a run) feeds the Run tab of the desk screen (`public/screens.js` `RunTab`, #211). The office installs the plugin in Paperclip itself (#222: the `adapter` write kind, `src/hq-writes/adapter.mjs`; the adapter state is read from `GET /api/adapters`; `office.mjs` has the install route and the `adapterDir` option). The run context is `deskCtx` in the snapshot (`SESSION_FIELDS`; `office.mjs` `fullSession` sets it from `s.paperclip.desk`), and the desk screen shows it (`screens.js` `RunContext`, `OfficeVocab.hq.desk`, with the context window of the session); a run with no context shows no block.
- Company memory (#205): `office.mjs` wires it (`memory`): page routes `GET /api/memory` (`?q=` searches, else the newest 50), `POST /api/memory/remember` (a fact the user adds, source `user`) and `POST /api/memory/forget` (ask-first kind `memory`: 409 until `confirmed: true`). The page is `MemoryPanel` in `public/hq.js` (HQ dialog and the Orientation memory step).
- Goals (#156): `office.mjs` has `startGoal`, `goalAgents` (idle agents of the same building), `goalTick` (a step ends with its agent's turn; a freed agent takes a waiting step; it calls `manager.check`), the model ladder wiring (`ready(building)`, `callsOf`, `dispatch` with `set_model`), and `/api/goal/start|approve|cancel|retry` (page group). Goals are saved as `persisted.goals` (`export`, `restore`) and the snapshot field `plans` is `createPlanBoard`. A connected Paperclip company (`persisted.paperclip.company`) refuses an office goal: 409 with `confirm: 'goal'` until `confirmed: true`.
- Office Managers (#204): routes (page group) `GET /api/managers`, `POST /api/manager/hire { building, name?, budgetDollars, confirmed? }` (answers `pendingApproval` too). The Manager board (`public/hq.js`) has the building pick and Hire Manager: a dialog with a name and the monthly budget (`OfficeVocab.plan.hireManager`), then the ask-first question with its painted Confirm hire.

### Features across the server and the page

- Orientation (#196, `orientation.mjs`): routes (page group) `GET /api/orientation`, `POST /api/orientation/step` (`{ step, status }` or `{ seen: true }`). The page (`reception.js`, `Reception.Orientation`) draws each step's own controls and keeps no copy of the list; it opens once when the server has not seen it closed and the browser key `ao-orientation` is not set, before the lobby tour, and again from the Reception and Ctrl+K. The company step (`CompanyStep`) shows the HQ runtime panel (`O.PaperclipRuntime`: install or connect, with its links for the first account and the board key approval, which stay the user's) and, once Paperclip runs with a key or is connected, a name and a building kind; `POST /api/paperclip/company` (`{ name, archetype, confirmed }`: 409 until the first account and the key exist, one `POST /api/companies` through `hq.write` (the write grid's Company cell, Confirm by default, then ask-first kind `write`; a name that exists is reused), then `connectHq`; `companyDraft` in `paperclip.mjs` checks the name and the kind).
- Agent characters (#150, `personas.mjs`): routes `/api/personas`, `/api/persona/save|delete`. The office puts `persona` on each session (`SESSION_FIELDS`; `office.mjs` `fullSession` uses `personaOf`). `OfficeVocab.persona` (`public/vocab-persona.js`) holds the words, the look, the cue rule, `pose` and `markOn`. `building.js` seats the bot with the persona's shape and color (a change seats it again). The page UI is `Characters.Dialog` in `public/characters.js` (`PersonasDialog`; More, Ctrl+K: Agent characters).
- Rituals (#151, `rituals.mjs`): served by `GET /api/recap?since=`; the snapshot's `rituals.merges` has the newest 20 merges. The shared rules are `OfficeVocab.rituals` in `public/vocab.js`: `on({ focus, reduced })`, the stand-up (`STANDUP` line, `standupDue`/`standupDone` per agent name per day, in `persisted.standups`) and `moments` (a merged moment plays once, within 10 minutes, and never while any request is open: it waits, the request does not). Focus mode is `persisted.focus` (`POST /api/settings/focus`, the snapshot's `rituals.focus`): it turns off the stand-up line, the merged moment (`building.js playMoments`: a DS `checkpoint` and a short `message` on the bot of the merged branch, seeded merges are never replayed), the bots' body language (`persona.js` `off`) and sound. Reduced motion turns off the page-side ones. The stand-up goes only to agents with the office tools (`STANDUP_KINDS` in `office.mjs`) and asks for a note with `office_room_update`, so the injection scan still reads it.

### Images in chat

Remote images in chat load only after a click. The rule is in the DS RichText (`components/bundle.js`: `remoteHost`, `imageShown`, `LoadCard`, `shownImg`): an http(s) image shows the card "Load image from <host>" until the user clicks; the click counts for that URL until the page reloads; `data:` and `blob:` images show at once; the image viewer asks the same way; images carry `referrerPolicy: no-referrer`. Agent replies reach it because `building.js` sends them as Markdown `message` events. Never render agent or tool text with your own `<img src>`, and do not send it with a `thumb` or image attachment of a remote URL. `test/rich.test.mjs` runs the bundle in a Node VM with the vendored React and a shallow renderer (stand-in hooks); use it for other DS logic too.

An office on a port other than 4317 (`OFFICE_PORT`, `npm run start:branch`) writes the same files with its port in the name, for example `.office-token-4392`, `office-hooks-4392.json`, `office-hooks-http-4392.json`, `office-mcp-4392.json`, `state-4392.json` and `history-4392.json`. Its settings files call `src/hook.mjs` and `src/mcp.mjs` with the port, so a session attached to it talks to it, and a session attached to the office on 4317 keeps talking to 4317. That office starts with its own empty notes, schedules and past sessions. An office on another port that ran here before this change keeps its agent token, so settings files it made still work. Its old notes and schedules stay in `state.json`. To probe the HTTP hooks of that office, run `npm run probe -- <port>`.
