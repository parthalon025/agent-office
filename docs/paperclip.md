# Paperclip HQ

> **Paperclip runtime (new).** The office can install and run Paperclip for you. See [Run Paperclip from the office](#run-paperclip-from-the-office) at the end of this page. Until the HQ page is rebuilt, the sections below describe the HQ that watches a Paperclip that you run yourself.

[Paperclip](https://github.com/paperclipai/paperclip) is the graph harness that runs a company of agents: goals, heartbeats, routines and budgets. The office supervises those agents: it holds the Claude Code calls of their runs for your answer, and shows them. The office can watch one Paperclip company as an HQ building in the city. It is off until you connect it, and the office works alone as before without it. The office only reads Paperclip. It never sends a heartbeat, assigns a task, runs a routine or changes a budget. The one change it can make is **Supervise in office** (below), after you confirm it.

- **Before you start.** Paperclip needs Node 24.11 or newer (the office needs the same). Run it on this computer in local trusted mode: `paperclipai run --bind loopback` (on a new data folder, `paperclipai onboard` first). The office connects only to an address on 127.0.0.1 and refuses any other host, `localhost` too. It does not sign in: a Paperclip in authenticated mode answers 403, and the office says so.
- **Create the company (Orientation, #199).** The Company step of Orientation (open it from the Reception or Ctrl+K) installs Paperclip or connects the one you run, then creates your company. You do two things in Paperclip yourself: create the first admin account, and approve the office's board key. The step shows both links and waits. Then you type a company name and pick a kind of building, and the office asks first, as the write grid's **Company** cell says (Confirm by default). It writes one company (`POST /api/companies`) and nothing else, then watches it. A company with the same name is reused, so a second try never makes two. The step is skippable and you can come back to it.
- **Connect.** Open **More**, then **Attach sessions**. Under **Paperclip HQ**, type the address (`http://127.0.0.1:3100` by default) and click **Connect**. With several companies, pick one. The office keeps the address and the company in `state.json` and connects again when it starts. **Disconnect Paperclip** stops the watch; Paperclip runs on.
- **The HQ building.** The company is the first building in the city, with a penthouse and a mast on its roof. Its sign shows its agents and its budget for the month. A pip per agent shows its state in Paperclip: working while a run is queued or runs, error after a failed run, else at rest. A Paperclip approval (hire an agent, a strategy) is Paperclip's, so it never shows as Needs you. Type in Ctrl+K to search Paperclip with the office: employees, floors, open tasks, goals, approvals and routines of the connected company are in the list under **Paperclip**. A pick opens the HQ at that item and marks it. Click the HQ (or Ctrl+K, **Paperclip HQ**) to see each agent's role, task, heartbeat, budget and supervision, and the routines with their next run.
- **Both schedulers run.** Paperclip runs its heartbeats and routines; the office runs its own schedules. Neither moves the other's.
- **Budgets.** Paperclip owns the budgets of its runs. The office shows them on the HQ and on the stats of each Paperclip bot, and sets no second limit on those runs. Office sessions keep the office spend limit.
- **Supervise in office.** An agent whose runs skip the office shows "Unsupervised". To hold its Claude Code calls here, open the **Agents** screen of a Security room, click **Paperclip** at the top of the screen, click **Supervise in office** on the agent, then **Confirm** on the wall. The office sends one change of that agent's adapter config to Paperclip: `engine: cli`, `dangerouslySkipPermissions: false`, and `--permission-mode default --settings <this office's office-hooks file>` at the end of its `extraArgs`. Its other arguments stay, but a flag that lets a run approve its own calls or turns off hooks goes, with its values: `--dangerously-skip-permissions`, `--allow-dangerously-skip-permissions`, `--permission-prompt-tool`, `--allowedTools` (`--allowed-tools`), `--managed-settings`, `--bare` and `--safe-mode`. All three settings are needed (spike #75): the default ACP engine approves every call and ignores the arguments, and without `--permission-mode default` the machine default (Auto) asks nothing. Only a `claude_local` agent can be set up. The office reads the agent from Paperclip again just before it sends the change, so a change you made in Paperclip a moment before stays, and once more after it: when Paperclip saved other arguments than the office sent, the feed says so and the agent shows what Paperclip saved. Claude Code loads only the last `--settings`, so an own settings file of the agent no longer loads after the change, and the feed names it. The agent shows Unsupervised until Paperclip has saved the change.
- **Its runs in the office.** A supervised agent's run is a terminal-type session in the building of its folder. Its bot card says "Paperclip <role>, Claude Code" with the company and agent as owner, its task line shows its Paperclip task, and its stats show its Paperclip budget. Its requests wait like an office session (a Paperclip run has no terminal dialog): 15 minutes, because the command hook waits up to 1000 seconds (`hook.mjs` posts with `node:http`, #128). This is true for every run with Paperclip ids in its environment, also a run of a company that the office does not watch. A request that waits too long is denied with a reason, and when Paperclip still marks the run succeeded, the feed says that the office denied a call of it.
- **What the office checks.** The office reads the command line of each run (Paperclip's `adapter.invoke` event). A run that starts without the office hooks, with a flag that lets it approve its own calls (such as `--allowedTools`, which Paperclip itself passes on a sandbox target), or on another computer is named in the feed, and the agent shows "Unsupervised: its last run skipped the office". An agent or a run that starts another program than `claude` (the `command` setting) is "Partly supervised": the office cannot tell if that program uses the office hooks. So is an agent with a flag that loads plugins, agents or settings (`--plugin-dir`, `--plugin-url`, `--agents`, `--agent`, `--setting-sources`, ...), lets something else answer a call (`--sdk-url`, `--remote-control`, `--channels`), or that the office does not know: Supervise in office leaves these flags as they are. The office reads the arguments the way Claude Code 2.1.318 reads them, so a flag inside the value of another flag does not count. A cloud session (`--cloud`, `--environment`) is Unsupervised. In the agent's `env` the office reads only the names, never a value, and never changes it: a name that turns off hooks or permissions (such as `CLAUDE_CODE_SIMPLE`) makes the agent Unsupervised, and Supervise in office is not offered until you remove it in Paperclip. A name of the families `CLAUDE_CODE_*`, `CLAUDE_BG_*` and `NODE_*` that the office does not know makes the agent "Partly supervised" (a login, a provider choice and `NODE_ENV` do not). A project or routine that Paperclip lists carries an `env` too: the office reads its names the same way. Every project of the company counts, because an agent can be given an issue of any project. When Paperclip lists no `env` for a project or routine, or lists 500 issues (its default cut), or a list does not load, the agent is "Partly supervised": the office never reads what it cannot see as empty. "Supervised" means the office holds every call Claude Code asks about. Claude Code does not ask for a call that an allow rule in a settings file of the run's folder or your home folder allows, and the office does not read those files. The office cannot see the environment of the Paperclip process itself, which Paperclip passes to its runs too. A model profile or an issue that overrides the adapter config makes the agent "Partly supervised" too. Agents of other kinds (`codex_local`, `process`, `http`, ...) never reach the office hooks: they show in the HQ as Unsupervised, and the office cannot set them up.
- **Not tested against a real Paperclip.** The routes and events come from the Paperclip source (0.3.1, checked again for the projects and routines routes and their `env` fields) and the spike on 2026.1023.0 (#75). The `engine` setting of `claude_local` is from the spike only: the 0.3.1 source has no such setting, so an agent without `engine: cli` shows Unsupervised; the tests use a fake Paperclip (`test/fixtures/fake-paperclip.mjs`). A live run with a supervised agent is still to do.

## Run Paperclip from the office

The office can install one pinned release of Paperclip, start it for you in its login mode, keep its board key in a file that only you can read, and stop it with the office. Open **More**, then **Attach sessions**. The **Paperclip runtime** part is above **Paperclip HQ**.

- **Install Paperclip.** Click it, then confirm. The office runs npm (its own JS file with node, because `npm.cmd` is a script and the office starts no shell) and installs `paperclipai` version 2026.1106.0 into `.paperclip-runtime` in the office folder. Git ignores that folder. npm downloads about 440 packages, runs none of their install scripts (`--ignore-scripts`) and needs the internet and a few minutes. Only Windows is verified: on Linux and macOS the embedded database may need the symlink step of its package. The office pins the SHA-512 of the package. It checks the result against it and calls anything else "not installed". The office never installs when a Paperclip already answers at 127.0.0.1:3100 (yours, or another program's), and it never changes yours.
- **Start Paperclip.** The office writes the Paperclip config once, in `%LOCALAPPDATA%\AgentOffice\paperclip` (an office on another port has its own folder, `paperclip-<port>`): login mode (`authenticated`), private, bound to 127.0.0.1, telemetry and update checks off. It uses its own Paperclip instance (`agent-office`) and its own database port (54339), so a Paperclip that you run yourself, with its data in `~/.paperclip`, is never touched. The office makes the first-run secrets of Paperclip (`.env` and `secrets/master.key`) as owner-only files. It checks Paperclip's health every 15 seconds. The first start makes the database and takes a minute or two. Once you start Paperclip, it starts again with the office until you click **Stop Paperclip**. If the office ends normally (Ctrl+C, a stop by process id), Paperclip ends with it. If the office is killed with no chance to run, Paperclip keeps running, and the next office takes it over.
- **Two steps are yours.** Paperclip in login mode has no account and no key at first, and the office does not invent either.
  1. **First account.** While Paperclip has no admin, the panel shows a one-time link (Paperclip prints it at the first start). Open it, create an account and finish the sign-up. That account is the admin. Or open Paperclip, create an account and choose **Claim this instance**.
  2. **Board key.** Click **Connect board key**. The office shows an approval link. Open it, sign in and approve the office. The office checks the key, then saves it in `%LOCALAPPDATA%\AgentOffice\paperclip-board-key.json`, readable only by you. No page of the office ever shows it. A board key is valid for 30 days (Paperclip's rule). The panel shows the date and asks for a new key when it expires.
- **Why not.** The panel says why when Paperclip does not run: an install error with the end of npm's output, "Another Paperclip runs" (port 3100 is taken by a Paperclip that the office did not start: connect to it in **Paperclip HQ** instead), "Port in use" (another program), or a start that failed with the last lines of Paperclip's output. If Paperclip answers in another mode than login mode, the office stops it.
- **Settings.** `OFFICE_PAPERCLIP_PORT` (default 3100) and `OFFICE_PAPERCLIP_DB_PORT` (default 54339) move the ports. `OFFICE_NPM_CLI` is the full path of `npm-cli.js` when npm is not next to node. If your global npm config uses a private registry, npm may answer E404 for `paperclipai`: install with `--registry https://registry.npmjs.org` once by hand in `.paperclip-runtime`, or fix your `.npmrc`.
- **Update Paperclip.** When the office ships a newer pinned release than the one installed, the panel shows **Update Paperclip**. Click it, then confirm: nothing changes without the Confirm. The office downloads the new release with npm into a staging folder (`.paperclip-runtime-next`) and checks it against its pinned SHA-512 while the old release keeps running. A download that fails or does not match changes nothing, and the panel says why. Then, if Paperclip runs, the office stops it, switches the folders (the old release waits as `.paperclip-runtime-prev`) and starts the new one. If the new release does not answer, the office puts the old one back and starts it again. Paperclip's data and the board key stay. A new release may change the format of its data, which an old release cannot always read: the office keeps hourly backups (Paperclip's own, 7 days). An older release that the office installed and checked itself stays usable until you update (`office-verified.json` in the install folder).
- **Where it lives.** The runtime panel is in the HQ now: **Ctrl+K**, then **Paperclip HQ**. **Attach sessions** shows its state and a button to the HQ.

### Connect to a Paperclip you already run

If you already run Paperclip, connect to it instead of installing one. In **Paperclip HQ** (Ctrl+K, then **Paperclip HQ**), under **Connect to your Paperclip**, type the address (127.0.0.1 only) and a board key, then click **Connect to Paperclip**.

- **What the office does.** It asks Paperclip who the key is, and nothing else. It installs nothing, starts nothing, stops nothing and changes nothing in your Paperclip. Install Paperclip, Start Paperclip and Update Paperclip are off while you are connected. The office never installs over your Paperclip.
- **The key.** Create a board key in Paperclip. The office checks it with Paperclip first. Then it saves it in `%LOCALAPPDATA%\AgentOffice\paperclip-board-key.json`, a file only you can read. No page, message or log shows it. The HQ uses it for its reads of that address and for no other address. A Paperclip in local trusted mode needs no key: leave the field empty. With an empty field, the office uses the key it saved for the same address.
- **Wrong address or key.** The panel says why: the address is not on 127.0.0.1, nothing answers there, something other than Paperclip answers, the key has the wrong shape, Paperclip does not accept the key (wrong, expired or revoked), or Paperclip is in login mode and you gave no key. Nothing is saved then.
- **Disconnect.** It deletes the saved key and the address. Your Paperclip runs on. The office connects again when it starts. If your Paperclip is not up then, the panel says so and you connect again.
- **While the office runs its own Paperclip,** stop it first. Two Paperclips are never used at once.

## The HQ building and the Lobby

When the office watches a company, the company is the HQ building in the city. Its floors follow the org chart: Records at the bottom, then the Lobby, then one floor for each reporting rank, with the top role (the CEO) on the top floor. Each employee has a pip on its floor. The city card shows one line: employees, open tasks, approvals that wait, and spend.

Open **Paperclip HQ** for the Lobby: employees, open tasks, approvals, goals and spend as cards, the approvals and goals that wait, the org chart and the live activity. When the office could not read a part, the card says Unknown, not zero. On a phone, the HQ is a card above the buildings. It lists each employee with its status, its task and how it is supervised, and what needs you: the approvals that wait and each employee whose last run failed. The approvals are decided in Paperclip, so the card has no Approve button.


**Costs** (Finance) is in the same dialog: spend per agent and per project for this month and the two before it, and the budgets (what each has used of its limit, and any employee a budget paused). It reads Paperclip when you open the HQ and only reads. Unknown stays unknown: a month or a cut that Paperclip did not answer says Unknown, never $0.00, and a month with a row of no known cost says "or more".

**Projects and workspaces** are rooms. Each Paperclip project is a room in the HQ list, with its workspaces and their folders. An employee sits in the room of its best open task (in progress first), in the workspace that task names, else the project's primary one. A project with no workspace says so; the office never invents a folder. Paperclip lists that the office cannot read give no rooms, not an empty room.

The org chart lists the floors from the top, each employee with a cable to its manager (a line in the accent color; an employee with no manager has a grey one) and a Manager list. The floors rebuild when Paperclip changes a reporting line, from the office or from Paperclip. Changing a reporting line is a write of the write grid (**Reporting lines**): pick a manager, then click Change reporting line. With Confirm (the default) that click is the confirmation, with Allow it sends at once, and with Deny the org chart is read only: the lists are off and the office refuses the call. The office sends one PATCH `{ reportsTo }` and nothing else. A change that would make a loop, or name a manager outside the company, is refused before any PATCH.

The office reads Paperclip through its own server. The page never calls Paperclip, and the board key never leaves the office: it goes to Paperclip as a bearer token and is in no answer to the page. Secret names show, secret values and approval payloads do not. If an update of Paperclip changes the shape of an answer the office reads, the office does not use that part, says so in the HQ and in the feed, and shows Unknown for it.

## Writes from the office

Every write to Paperclip goes through one writer, and the **write grid** decides each kind of write: **Confirm**, **Allow** or **Deny**. The kinds are hires, pause and retire, budgets, approvals, reporting lines, routines, invites and access, secrets, tasks, comments and the first company. By default every kind is Confirm, except tasks and comments: your own task edits and comments save at once. Secrets offer Confirm and Deny only, never Allow. A change to a looser cell (Deny to Confirm, Confirm to Allow) needs a second, painted Confirm. A stricter change applies at once. The grid is saved in the office state, and only the cells you set.

- **Allow** sends the write. **Deny** refuses it and sends nothing, even with a Confirm. **Confirm** asks first: the office answers with the question ("Approve an approval in <company>?") and sends nothing until the same call comes again with the confirmation.
- Before it asks or sends, the office reads the task, approval or employee the write names. It must be in the connected company, and an approval must still wait for a decision. A write that cannot happen is refused, not asked.
- Every write leaves a feed line ("Wrote to <company>: ..."), and so does a refusal by the grid or by Paperclip.
- The first writes are: create a task (with an optional first assignee), create a sub-task of a task, set the status of a task (the Manager reports its steps this way, see the [Manager board](manager.md)), assign a task, comment on a task, approve, reject or request a revision of an approval (with a note), hire an employee (see below; the office Manager is hired the same way), and create the first company (it needs no connection: it names the loopback address, and a company with that name is reused with no write). The other kinds are in the grid, and each gets its writes with its own page.
- Routes (page token only): `GET /api/hq/grid`, `POST /api/hq/grid/set` and `POST /api/hq/write`. The answer of a write carries ids only, never a body from Paperclip, and the board key is in no answer.

## Hiring at the HR desk

Open **Hire an employee** in Ctrl+K (it shows once a company is connected), or do the **First hire** step of Orientation. The HR desk has a role card for each role (Engineer, Quality, Designer, Project manager, Researcher, Operations, Security, General). Pick a card, then set the name, who the employee reports to, the agent kind, the model (optional), the monthly budget and the skills.

- **A budget is required.** The office refuses a hire with no budget, or a budget of zero, and sends nothing to Paperclip. The budget is in dollars a month.
- **The new employee uses the office adapter** (`agent_office`), so its runs go through the Security room and it shows as Supervised. The default agent kind is Claude Code, and the employee works in a room of its own (`isolation: worktree`).
- **The Confirm shows exactly what it creates.** Hire asks first. The question names the role, the manager, the agent kind, the model, the budget and the skills, and nothing is sent until you press Confirm hire. The write grid cell Hires can set Allow (no question) or Deny (no hire).
- **Onboarding.** With the same Confirm, the office sends one first task to the new employee: read the room notes and post a stand-up note with `office_room_update`. This is a second write through the same writer (kind task). If it fails, the hire stays and the page says so.
- Route (page token only): `POST /api/hq/hire` `{ name, role, manager?, agentKind?, model?, isolation?, budgetDollars, skills?, welcome?, confirmed? }`, and `GET /api/hq/hire-desk` for the role cards. The hire itself is `POST /api/companies/<company>/agent-hires`.

## The office adapter

The office ships an adapter plugin for Paperclip, `agent_office` (folder `src/integrations/paperclip-adapter`). When Paperclip wakes an employee on this adapter, the plugin hands the run to the office. The office runs it as a normal office session with the employee's agent kind, so the Security room decides every call, a call that asks you waits in Needs you, and the employee has a bot and a room. The office sends the result, token usage, cost and a log of the run back to Paperclip. An employee on the office adapter shows as **Supervised** at the HQ, whatever its agent kind.

- **Install the plugin.** Paperclip must run on this computer. As the board, send `POST /api/adapters` to Paperclip with `{ "localPath": "<office folder>/src/integrations/paperclip-adapter" }`. The office does not do this for you yet. Paperclip loads external adapters at start, so restart it. The plugin finds the office from the token file named in the `AGENT_OFFICE_TOKEN_FILE` environment variable. A Paperclip that the office starts has it set. For another Paperclip, set it to the `.office-token` file of the office (`.office-token-<port>` on another port), or set `tokenFile` in the adapter config of an employee.
- **Adapter config** (an employee with adapter type `agent_office`): `agentKind` (default `claude-code`; any office agent kind), `model`, `cwd` (default: the workspace Paperclip gives the run), `isolation` (`same` by default, or `worktree` for a new git worktree on each run), `promptTemplate` (`{{agent.name}}` and `{{agent.id}}` are filled in), `tokenFile`.
- **What a run does.** The prompt is the template (or "Continue your work.") with the task and the wake reason. The session opens in the folder of the run, or in a worktree of it. A refusal of the office reaches Paperclip as the error of the run: an agent kind that is off (an agent the office cannot supervise fully stays off until you turn it on in the Security room, and runs only in a room of its own), an agent kind that does not report cost (nobody can answer the question in a run: decide it in the Security room first), or a spend limit. The run ends with the first turn. The session closes and stays in Past sessions. If you close the session in the office first, the run fails and says so.
- **The transcript at the desk.** A session that is a run of this adapter has a **Run** tab on its desk screen. It shows the log Paperclip reads (replies, calls, failures and the calls that wait in Needs you) and stays after the run ends. The page gets it from `GET /api/paperclip/transcript?uid=`; a session that is not a run has none (404).
- **Cost and usage.** Paperclip gets the cost the agent reported. An agent that reports none gives no cost, and Paperclip shows it as unpriced, never as $0.00. A local model reports $0.00. Usage is given only when the agent reports input and output tokens.
- **The run waits for you.** A call in Needs you holds the run. The plugin asks the office for news every 25 seconds, so a run can wait for hours. If the office stops, the run fails ("Agent Office lost the run").
- **Context on the desk.** The desk screen of an employee run has a **Run context** block: the wake reason, whether the session is fresh or resumed and why, the instructions file, the skills, and the share of the context window in use. The office shows only what the run carried or the session reported, and says "not reported" or "unknown" for the rest. A session is always fresh today. It says why: Paperclip saved no earlier session, it is another task, another folder, the instructions changed, or the office does not resume yet. The plugin reads these from what Paperclip passes it (`runtime.sessionParams`, `config.instructionsFilePath`, `config.paperclipRuntimeSkills`, `context.wakeReason`); the names are from Paperclip's adapter interface and are not checked against a real Paperclip.
- **Not done yet.** The office does not install the plugin for you, a new wake starts a fresh session (no resume), and an employee is not hired on this adapter by default yet. The plugin is tested with a stand-in Paperclip host, not with a real Paperclip.

## Company memory

The company has one memory that its employees share. It is free and local. It stays on this PC unless you choose another adapter later.

- **Where.** One SQLite file per company, in `%LOCALAPPDATA%\AgentOffice\memory\` (`memory-<port>` for an office on another port). Only you, SYSTEM and Administrators can read it. It is outside the office folder, so an update never touches it.
- **Keyword search always works.** It needs no model and no setup. If LM Studio or Ollama runs with an embedding model loaded, search also finds meaning, and the Memory panel says which model does it. The office never loads or downloads a model. Set `OFFICE_EMBED=off` to turn the model search off.
- **Needs Node with `node:sqlite`.** Where it is missing, memory is off and the panel says why. Runs start without memory.
- **Where it comes from.** Every memory shows who made it: you, or an employee with its task and run. A run that ends well adds its last reply. You can add a fact in the Memory panel.
- **What the employee sees.** At each wake, up to five matching memories go in front of the prompt, marked as notes and not instructions. They are left out when the whole prompt would pass the office message limit.
- **What is refused.** Text that holds a secret, an instruction to ignore earlier instructions, or hidden characters is refused before it is stored (the same scan as the notes board).
- **Forget.** The Memory panel (HQ dialog, and the Orientation step) lists, searches and forgets memories. Forget asks first.
- **More adapters.** The store is behind one interface (`OFFICE_MEMORY_ADAPTER`). Only the built-in SQLite adapter exists today. Milvus, mem0 and a Paperclip memory adapter are not built.
