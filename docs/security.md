# Security

How the office keeps agents in check, who can reach it, and what it keeps on disk. The page controls are in [Using the office](using-the-office.md). The full audit is in [the security review](security-review.md).

## The Security room

The ground floor of each building has a Security room with six wall screens: Files, Commands, Network, Secrets, Agents and Spend. Each screen has one row per kind of tool call and one column per agent kind (Claude Code, Hermes, dsh, OpenClaw, local model, Agent Framework, cloud agent: Azure AI Foundry, Copilot Studio, Cursor cloud agent and the Hermes gateway share it). A cell that does not apply to an agent kind names why instead (a cloud agent has no file cells: "No files"). Click a screen to look at it, then click a cell: Ask, Allow, Deny. Allow makes the cell amber with a Confirm on the wall; Ask and Deny apply at once. Secret files and settings files that run code offer only Ask or Deny. The rules are for all buildings, or for this building only. The office answers Allow and Deny at once and writes a line in the activity feed; Ask waits for you as before. By default every cell is Ask, reads and edits inside the worktree too: the office answers a request only when you set a cell to Allow or Deny. A default cell makes no new prompts: Claude Code asks what it asks today (it reads files in its folder without asking), the office holds those requests, and the Permissions choice of the Open dialog applies. The wall says "Partly enforced" there; click the cell once to set Ask, and the office then makes Claude Code ask. **Use default** under a cell takes your rule back. (The local model keeps what it did before: its reads and edits in its folder run without a question, also in a folder outside git, until you set them to Ask.) Inside the worktree means a git worktree: a session that started in a folder outside git, in your home folder or at a drive root has no worktree, so its reads and edits fall under Read or edit outside it. Files that run code at sign-in or in every shell (the Startup folder, PowerShell and shell profiles) and the office's own `state.json` and `history.json` count as settings files that run code. So does an edit of the office's own code (`src/`, `launch.ps1`, `public/` and the other files in the office folder, not its Markdown documents or the worktrees in `.claude/worktrees`), whatever folder the session works in: an Allow on edits inside the worktree does not cover it. Ctrl+K **Permissions** goes there. A cell the office cannot enforce for an agent says "Not enforced" and why. "Partly enforced" marks an Ask that Claude Code decides by itself: for outside files, shell commands, web and MCP calls, Claude Code asks only when its own allow rules and permission mode say so, and the office holds what it asks. For secret files, settings files and reads or edits inside the worktree, the office makes Claude Code ask once you set the cell to Ask. On the Spend screen, minus stops at $1; No limit (type 0) needs the Confirm on the wall. While the office watches a Paperclip company, the Spend screen also shows the company's cost this month and its budget, for example "Paperclip, this month: $12.40 of $100.00 (12%)." When the office cannot read the cost it says "cost unknown", never $0.00. The rules work only while the office runs: when it is stopped, Claude Code decides alone, and a Deny does not apply. The screens take pointer clicks only: they have no keyboard path.

The office also proposes rules from your own answers. It looks at the requests you answered and, when you answer the same kind of request the same way many times, it offers a rule on the wall. It never applies one by itself: you apply it with the painted Confirm, and you can withdraw it later ([ADR 0009](adr/0009-earned-trust-proposals-only.md)).

## Access and tokens

- The server listens on 127.0.0.1 only and rejects other host names.
- Two tokens keep agents and you apart. The **agent token** opens only the routes that hooks and the MCP server use (`/hook`, `/mcp/...`). It is kept in `.office-token` and in the HTTP hooks file, and reused across restarts, so running sessions keep working. The **page token** opens only the page's routes (`/events`, `/api/...`): answers, sessions, extensions, schedules. Neither token opens the other routes.
- The page token is new at each start and is never in this folder, so an agent that reads files here cannot approve its own requests. The page itself holds no token: the launch link carries a one-time code, and the page trades it for a cookie that page scripts cannot read. Your own tools (`npm run probe`, `npm run smoke`, a second `npm start`) read the page token from `%LOCALAPPDATA%\AgentOffice\office-page-<port>.json`.
- Only your Windows user, SYSTEM and the Administrators group can read the files with a token and the settings files whose commands sessions run. Other users, and groups such as Users, Authenticated Users and Everyone, cannot. SYSTEM and Administrators keep access because they can take ownership of any file anyway, and backup and antivirus need it. If the office cannot set that, it prints a warning when it starts. The office folder itself keeps the permissions of its drive; on a shared computer, keep it in your user folder.
- Requests from another site or another port of this computer are refused, and every change must be sent as JSON. No page can show the office in a frame.
- The page loads its scripts, style sheets and fonts from the office only. Nothing comes from a CDN or a font service. Its content security policy refuses scripts, style sheets and fonts from any other place, and inline scripts.
- An image from another site in an agent's reply shows as a card with a **Load image from** button and the site name. Nothing goes to that site until you click; point at the button to see the full address first. The click loads that one image until you reload the page, and the request does not send the office address. Images that are part of the message itself (`data:`) show at once.
- The office sends hook data to your own machine only. Hooks forward short fields: the tool name, a path or command, and the prompt. A permission prompt also carries the full input so the card can show the change.
- "Always allow" writes the rule Claude suggests to that project's `.claude/settings.local.json`, and only when you click it.
- Creating a pull request runs `git push` and `gh pr create`. The office asks you to confirm and lists the steps first.
- The office never edits `~/.claude/settings.json` or your credentials.
- Saved sessions (`history.json`) contain Claude's replies, and `state.json` keeps schedule prompts and room notes. They stay on this machine, and only your Windows user, SYSTEM and Administrators can read them (set when the office starts). An agent edit of `state.json`, `history.json` or their per-port files is rated high, because schedules in them run later.
- The cloud kinds (Azure AI Foundry, Copilot Studio) are off until you set an endpoint and a token. The office never signs in and never asks Azure for a token. It sends the token you made to the `https` Microsoft host you set, and to no other host. The token is never shown in the page, the chat or the feed, and the office does not write it to any file. At start the office takes `OFFICE_*_TOKEN` and `OFFICE_*_TOKEN_FILE` out of its environment, so the sessions and commands it starts do not get the token or the path to its file. Keep the token file outside the folders your agents work in.
- Paperclip HQ connects only to 127.0.0.1 and follows no redirect. The one secret it keeps is the board key, in a file only you can read; the key never reaches a page, the feed or `state.json` (ADR 0010). Every write to Paperclip goes through one writer, and the HQ write grid decides each kind (Confirm, Allow or Deny); Supervise in office also waits for the Confirm on the wall, and a Deny in the grid stops it. An employee on the office adapter is as supervised as its agent kind (see [Paperclip HQ](paperclip.md#the-office-adapter)).
- Remote access is off until you set it up (see [Remote access](remote-access.md)). The office never opens a port: it listens on 127.0.0.1 only, and the agent routes (hooks, MCP, the OpenClaw gate) refuse every remote request.

## Decisions and the review

- [Security review](security-review.md): the audit of issue #27, finding by finding.
- [ADR 0001](adr/0001-ungated-agents.md): agents that the office cannot hold are labeled, off by default and run in their own worktree.
- [ADR 0003](adr/0003-in-scene-controls-no-a11y-path.md): the Security room screens have no keyboard path.
- [ADR 0004](adr/0004-openclaw-config-read-not-written.md): the office reads the OpenClaw config and never writes it.
- [ADR 0005](adr/0005-paperclip-watched-not-driven.md) and [ADR 0007](adr/0007-paperclip-goal-handoff-write.md): what the office may write to Paperclip.
- [ADR 0008](adr/0008-remote-access-cloudflare-access.md): remote access through Cloudflare Access.
- [ADR 0009](adr/0009-earned-trust-proposals-only.md): earned trust proposes rules and never applies them.
